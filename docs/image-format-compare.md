# 개발 요청 · OS 이미지 광고 생성기의 포맷별 디자인

**대상** 브랜디액션 OS의 콘텐츠 자동화 → 이미지 광고(`/content/images`). 기준 사용자는 자기 브랜드의 광고를 만드는 운영자다. MYIN 무료 진단 다섯 장은 구현을 검수하는 기준 예시다.

## 대표 피드백을 제품 동작으로 반영

| 피드백 | 생성기가 해야 하는 일 | 인수 확인 |
|---|---|---|
| 포맷은 괜찮지만 폰트와 카드 디자인이 같다 | 각 포맷에 맞춰 제목 서체·계층, 사진 크롭, 구도와 CTA 표현을 함께 보존한다. | 새 프로젝트의 같은 입력으로 말풍선·갈림길·빈 검색·입력창·멈춘 손끝이 각각 승인한 디자인으로 나온다. |
| 이번 시안에서만 이렇게 나오면 안 된다 | 일반 작업에서 창고 포맷을 선택하고 작업의 브랜드·문구·등록 사진으로 제작한다. | MYIN 예시를 열지 않고 다른 브랜드의 작업을 만든다. 시안과 ZIP에 입력한 브랜드와 사진이 쓰이는지 확인한다. |
| 포맷만 바꿔 비교하고 싶다 | ‘포맷만 비교’ 묶음에서는 소구·브랜드·제목·설명·CTA·원사진·크기를 함께 고정한다. 선택한 포맷당 한 장을 만든다. | 후보 중 어느 한 장의 카피나 사진만 바뀐 가져오기 결과를 거절하고 기존 결과를 보존한다. |
| 선택한 안으로 다음 테스트를 이어가고 싶다 | 기준 시안의 포맷·디자인 버전을 계승한다. 소구, 카피, 이미지 테스트마다 지정한 변수만 바꾼다. | 최종 검수 후 다시 열고 기준 시안을 선택해 소구 → 카피 → 이미지 단계를 진행한다. |
| 다운로드한 것과 본 화면이 같아야 한다 | 창고 포맷은 한 제작 함수에서 만든 PNG를 미리보기와 내보내기에 사용한다. | 개별 PNG·ZIP 속 PNG·미리보기의 크기와 바이트를 대조한다. 이전 버전의 저장 기록은 기존 디자인과 이력을 보존하고 승인 기록이 비어 있는 묶음은 포맷 검토부터 진행한다. |

## 생성 화면에 포함할 제작 방식

- 처음 만들기에서는 목표·퍼널·등록 사진에 맞는 포맷을 고르고 후보 수를 정한다. 포맷을 승인한 뒤 확정 카피를 입력하거나 구독 AI에 카피 준비를 맡긴다.
- 포맷 비교에서는 공통 입력 한 세트로 선택한 연출당 한 장을 만든다.
- 소구 테스트에서는 사용자 지정 후보 수만큼 같은 포맷·사진·CTA에 다른 구매 이유와 그 이유를 설명하는 문구를 넣는다.
- 카피 테스트에서는 선택한 소구·사진·포맷을 고정하고 지정한 카피 항목을 바꾼다. 이미지 테스트에서는 선택한 소구·카피·포맷을 두고 등록 사진을 바꾼다.
- 단독 제작은 이전 테스트의 승자 없이 새 요청에서 시작한다.

## 제작 가능한 창고 포맷

| 포맷 | 포맷에 붙는 연출 | 입력할 사진 |
|---|---|---|
| M01 속마음 말풍선 | 손글씨, 인화사진, 잉크 도장 CTA | 표정과 행동을 함께 읽을 수 있는 장면 |
| A04 질문 갈림길 | 두 선택지로 뻗는 안내 표지, 굵은 간판 글자와 방향 CTA | 작은 원형으로 잘라도 주체가 식별되는 장면 |
| A10 검색 결과의 빈칸 | 지면의 검색어와 빈 렌즈, 검은 CTA | 작은 반사 면에 쓰일 피사체 |
| D12 미리 채운 입력창 | 크게 자른 인물과 입력문, 커서·전송 화살표 | 표정이 크롭 안에 남는 인물 사진 |
| M09 손이 멈춘 한 컷 | 흑백 확대, 명조 제목, 주홍 화살표 | 클릭·선택 직전의 손끝과 대상이 보이는 장면 |

이 다섯 포맷의 기본 제작 크기는 1080×1350이다. 저장한 시안의 글꼴·카드·규격 변경과 내보내기의 보호 영역은 [제작 후 디자인 편집](image-ad-safe-zones.md)을 따른다. 창고 73종 중 나머지 68종은 조사·기획 레퍼런스다. 기존 일반 템플릿 12종도 계속 사용할 수 있다. 새 포맷을 제작 가능 목록에 올릴 때는 실제 광고 출처와 교체할 입력, 전용 렌더러 및 버전을 연결한다. 예시 이미지 한 장을 창고에 저장한 것만으로 제작 가능 상태가 되지는 않는다.

## 개발자 검수 순서

1. 실제 작업 화면에서 새 프로젝트를 만든다. 자기 브랜드 이름과 자기 프로젝트의 사진을 넣고 위 포맷들을 고른다.
2. 확정된 공통 문구로 직접 만들거나 기존 구독 도구 연동 경로에서 결과를 가져온다. 프로젝트의 등록 사진과 지정한 포맷 및 변수 고정 조건이 유지되는지 확인한다.
3. 저장·다시 열기·기준 선택·후속 테스트·PNG 및 ZIP 내보내기를 같은 프로젝트에서 확인한다. 다른 브랜드로 프로젝트를 바꾸고 앞 작업의 임시 카피나 사진이 새 작업에 섞이지 않는지도 확인한다.
4. 기존 MYIN 샘플 다섯 장은 디자인 회귀 확인에 사용한다. 예시 재현, 로컬 OS 검증, 실제 운영 계정 검수와 배포는 각각 기록한다.

이후 대표가 주는 소재 피드백도 이 요청서에 **어떤 입력에서 어떤 문제가 보이는지 → OS 생성 규칙에서 바꿀 부분 → 다른 작업에서 재현할 인수조건** 순으로 반영한다. 예시는 해당 변경점을 확인하는 데 사용한다.

제작 단계와 파일 제공 조건은 [이미지 광고 승인 순서](image-ad-approvals.md)를 따른다.
