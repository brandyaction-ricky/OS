# Brandy OS 운영 QA 보고서

- 점검일: 2026-08-30 KST
- 대상: https://brandyaction-os.vercel.app
- 범위: 관리자 로그인 후 전체 37개 화면, 주요 열기·필터·탭·내비게이션 버튼, 비로그인 API 보안 경계

## 결론

전체 메뉴는 404 없이 열렸고, 기존 DB·인증·Telegram 연결은 유지됐다. 콘텐츠 7개 화면과 사람 승인 게이트도 운영 코드에 포함돼 있다. 실제 운영 데이터를 생성·변경·발행하는 버튼은 데이터 훼손과 외부 발행을 피하기 위해 폼 열기와 권한·계약까지만 확인했다.

이번 점검에서 사용자에게 동작하는 것처럼 보이지만 아무 반응이 없던 버튼과 지식 목록 초기 로딩 문제를 수정했다. 이후 원본 `studio` 전달본 전체와 다시 대조해 범용 CRUD로 남아 있던 콘텐츠 핵심 공정을 전용 화면과 API로 이식했다. 자동 검증은 37개 테스트, ESLint, TypeScript, Next.js 프로덕션 빌드가 모두 통과했다.

## 콘텐츠 반영 상태

초기 5차 반영에는 메뉴와 공통 데이터 계약은 있었지만, 전달본의 페이지별 동작을 다시 대조한 결과 `주제·기획`, `원고·스크립트`, `영상 성과`가 범용 CRUD 수준에 머문 누락이 확인됐다. 이번 후속 작업에서 다음을 보완했다.

- `정본 기반 생성 → 자가검수 → 사람 검토 → 최종 승인 → 예약` 상태 흐름
- 주제·기획, 원고·스크립트, 제목·썸네일, 숏폼 편집, 발행·업로드, YouTube 관리, 영상 성과 화면
- 외부 발행 전에 사람 승인을 요구하는 서버 계약
- 콘텐츠 AI 자격 증명이 없을 때 가짜 결과 대신 연결 대기 상태 표시
- 채널 모으기 → 터진 영상 발굴 → 틈새 확정 3단계와 기획 후보 채택·HANDOFF 저장
- 기획/패키징/자료/축 확정/설계표/초안/다듬기/발행 원고 8단계와 대표 결재 배너
- 제목·썸네일 후보의 실제 채택/해제 저장
- 조회·CTR·시청지속률·전환을 위계별로 보는 영상 성과 전용 화면
- 레거시 `/contents`와 섹션 루트 URL의 안전한 첫 화면 리다이렉트
- 페이지별 브라우저 제목, 시맨틱 브레드크럼, CSV 업로드와 구성원 선택 접근성 개선

### 키 연결 후 실검증 필요

- Claude 정본 실행: 주제 브리핑, 원고 초안, 제목·썸네일, 쇼츠 구간, 파생물, 유튜브 발행 키트의 실제 생성 품질과 자가검수 결과
- YouTube Data API: 운영 환경에서 시장 검색 쿼터·키 제한·응답 시간 확인
- 파생 데이터 생성 후 쇼츠 구간 채택 → 제작 대기, 검토 → 승인 → 예약 전체 흐름
- SEO 칼럼의 실제 `deriv_html` 구조와 자사몰 게시기 전달 계약

YouTube Data API 키로는 공개 영상 검색·조회수 등은 읽을 수 있지만 CTR·시청지속률과 실제 업로드는 검증할 수 없다. CTR·지속률은 YouTube Analytics OAuth가, 업로드는 OAuth 사용자 승인과 갱신 토큰이 추가로 필요하다.

### YouTube OAuth 업로드 구현

- 관리자 전용 Google OAuth 연결·콜백·연결 해제 API 추가
- `youtube.upload`, `youtube.readonly` 범위와 offline 갱신 토큰 사용
- OAuth `state` 서명·10분 만료·HttpOnly/SameSite 쿠키로 CSRF 방어
- 갱신·접근 토큰은 AES-256-GCM 암호화 후 사용자별 Supabase 테이블에 저장하며 브라우저·로그에 반환하지 않음
- 최종 승인 체크 후 비공개/일부공개만 허용하고 YouTube resumable 세션으로 브라우저→Google 직접 업로드
- 업로드 결과의 채널 소유권을 재검증하고 발행 기록과 영상 URL 저장
- 운영 적용에는 `202608300007_youtube_oauth.sql`, OAuth 환경변수, Google Cloud 승인 리디렉션 URI 등록이 필요

### 로컬 콘텐츠 데이터 동기화 후속 개발

5개 세션 문서를 최신 `main`과 다시 대조한 결과, 화면·정본·승인 공정은 반영됐지만 로컬 `radar.db`의 기존 콘텐츠를 OS로 옮기는 정식 경로가 남아 있었다. 아래를 추가했다.

- 관리자 전용 `/api/v1/content/import` 추가
- `source_content` → 원본 롱폼, `derivative_content` → 검토·발행 대기목록, `kpi_snapshots` → 영상 성과로 매핑
- 로컬 ID를 `metadata.legacyId`로 보존해 동일 스냅샷 재업로드 시 중복 생성 대신 갱신
- 원본이 없는 파생 항목은 건너뛰고 결과 건수로 명시
- 가져온 파생 항목에도 사람 검토·최종 승인·예약 게이트 유지
- `scripts/export-radar-snapshot.py`로 실제 전달본 SQLite 스키마를 OS JSON 계약으로 변환
- 발행·업로드 화면에 관리자 전용 `로컬 자료 가져오기` 추가
- 5MB·원본 1,000·파생 3,000·성과 3,000건 제한과 서버 스키마 검증

검증 결과: 합성 SQLite의 원본·파생·성과 변환 통과, Node 테스트 42/42, ESLint, TypeScript, 프로덕션 빌드 통과. Google OAuth 계정 연결과 실제 외부 업로드는 사용자 요청에 따라 별도 단계로 유지한다.

### Claude 운영 실호출 후속 수정

운영 제목·썸네일 화면에서 기존 QA 원본 1건으로 Claude 정본 실행을 1회 호출했다. 환경변수와 Anthropic 요청은 정상 동작했지만, 자유 형식 JSON 응답이 파서 계약과 맞지 않아 `CONTENT_GENERATION_INVALID`로 종료되는 문제를 재현했다.

- Anthropic Messages API의 `output_config.format.type=json_schema` 구조화 출력 적용
- 기획·원고·제목 패키지·쇼츠·파생·유튜브 키트별 JSON Schema 분리
- 두 번 생성하던 초안→검수 호출을 정본 기반 단일 구조화 호출로 합치고, 제출 전 자가검수·수정·점수·검토 결과를 같은 응답에 포함
- 콘텐츠 유형별 출력 토큰 상한을 7,000~14,000으로 조정
- `stop_reason=max_tokens`를 별도 오류로 처리해 잘린 JSON을 일반 형식 오류로 오인하지 않게 개선

수정 후 Node 테스트 42/42, ESLint, TypeScript, 프로덕션 빌드 통과.

첫 구조화 출력 배포의 운영 재호출에서는 Anthropic API가 `400`을 반환했다. 공식 JSON Schema 제한과 대조해 raw schema의 `minimum`·`maximum`이 지원되지 않는 제약임을 확인했다. 수치 범위는 설명과 저장 전 검증으로 유지하고, Claude에 전달하는 스키마에서는 해당 키워드를 제거했다.

최종 운영 재검증에서는 같은 QA 원본으로 Claude 정본 실행이 정상 완료됐다. 제목 후보 8개가 생성됐고 후보 설명·훅·자가검수 점수와 채택 상태가 화면 및 저장 계약에 맞게 표시됐다. 앱 콘솔 오류는 0건이었으며, 운영 헬스에서 DB·인증·Claude·YouTube·YouTube OAuth·Telegram이 모두 `ready`로 확인됐다. Google 계정 승인과 실제 채널 업로드는 사용자 요청에 따라 별도 연결 단계로 남긴다.
