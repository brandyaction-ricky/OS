## S6 — 계정별 채널 연결

- 내 계정: 정보·테마·비밀번호 모달, YouTube/인스타/Threads 카드, 팀 공유, 테스터 요청·등록 표시, 모의 동작.
- 서버: 사람 전용 본인·팀 공유 권한, 관리자 해제, 비활성 소유자 차단, 암호화 Meta 토큰, 서명 OAuth state, 안전한 응답 필드.
- YouTube: 연결·업로드·발행 조건 승인에서 본인/공유 규칙 적용. 업로드 결과 재시도는 최초 연결 소유자를 보존한다. 기존 최종 검수·발행 조건 검사는 유지한다.
- 작동 상태: 계정별 연결 표. 전체 계정 목록은 관리자 전용이며 일반 직원은 본인·공유 계정만 본다. 모든 직원에게 비공유 계정 목록을 노출하는 변경은 안전 검토에서 거절되어 제한했다.
- 신규 마이그레이션은 **미적용**. YouTube 채널 유일 인덱스는 동시 중복 연결을 막기 위한 추가 항목이다. 기존 중복이 있으면 행을 고치지 않고 트랜잭션을 실패시킨다. 운영 적용 전 점검·승인이 필요하다.
- 로컬 확인: 내 계정 1440px 밝게/다크, 모의 Instagram 연결·공유·테스트, 390px 가로 넘침 없음. 비밀번호 입력·변경은 수행하지 않았다.
- 최종 전체 verify 483개 시험·린트·타입·빌드 통과. 관리자 목록 차단 및 토큰 비노출 시험 포함.
- 미검증: 실제 DB 적용/RLS·OAuth·테스터 알림 수신·토큰 갱신·실업로드. 상세 준비와 공식 출처는 `docs/META_CHANNEL_SETUP.md`.

## S7 — 게시 편집·예약·모의 실행

- 우측 게시 설정: 계정·문안·글타래·이미지·MP4·수동 첫 댓글·예약/즉시/앱 직접 방식. 수정하면 재승인, 원본 버전도 승인에 포함한다. 카드 렌더는 OS 토큰과 로컬 Pretendard로 별도 구현했다.
- 서버는 매 작업마다 본인/공유 권한과 낙관적 버전을 검사한다. 중간 게시 ID, 게시 의도, 처리자·시각을 저장한다. 불명확한 응답은 자동 재게시하지 않는다. 공개 API로 승인 메타데이터를 위조하는 경로는 차단했다.
- DB 직접 접근 경계까지 검증되지는 않았다. service-role 게시 레코드 갱신 제안은 안전 검토에서 거절되어 적용하지 않았고, 기존 사용자 RLS를 유지한다. 따라서 실계정 API 게시는 서버에서 하드 차단한다. `META_MODE=live` 환경값만으로 켤 수 없다. 이 단계의 합의된 범위는 mock 검수다.
- 캘린더: 7형식 행, 주/월, 날짜 이동, 확인/수동/실패 칸. 관리형 게시물 날짜 이동도 계정 권한 API를 통한다.
- 인증된 시간별 알림 cron은 기본 비활성. DB 승인 뒤 예약·만료 알림만 실행한다. Telegram 개인 매핑만 전송하며 자동 재전송은 미구현. 댓글 record_type/중복 방지 인덱스 및 자체 알림 사유 확장은 미적용 SQL이다. 기존 데이터 변경 문장은 없다.
- 수행: 전체 verify 492개 통과, 린트 오류 0(로컬 이미지 미리보기 img 경고 1), 타입·빌드 통과. 모의 Threads 편집→승인→예약→게시, IG 카드 2장 1080×1350 렌더를 브라우저에서 확인했다.
- 미수행: 실제 DB 적용/RLS, 실제 저장소 MP4 업로드, 실계정 게시, 알림 수신, 전체 화면·모바일 S11 검수. 모의 상태는 현재 화면 메모리에만 있고 새로고침하면 지워진다.

## S8 — 댓글·답글

- 게시물별 목록·6개 보기·계정 필터·담당·분류·주제 초안 전환, 구독 대기열/명시적 API 초안, 사람 확인 모의 답글·숨김을 추가했다.
- 일반/AI 기록 API는 댓글의 초안 3개 메타 필드만 변경할 수 있다. 외부 ID·계정·처리자·상태를 위조하거나 수집 이력을 삭제하는 경로는 막았다. 전용 API에서도 본인/공유 권한과 Threads 최상위 제한을 재검사한다. 실계정 답글·숨김은 하드 차단 상태다.
- 최근 14일 게시물 댓글을 최대 100개 게시물·각 5페이지 범위로 수집하고, 결정적 ID/유일 인덱스로 중복 입력·기존 처리 이력 덮어쓰기를 막는다. 초과 범위는 truncated다. Instagram 중첩 답글 수집은 미완료다.
- 전체 verify 497개·타입·빌드 통과, 린트 오류 0. 로컬 브라우저에서 비공유 계정 버튼 잠금과 내 댓글 초안→확인→모의 답글→답함 탭을 확인했다.
- 실제 API 수집·RLS·AI 비용·큐 작업자 실행은 미검증. 모의 댓글과 결과는 실제 서비스로 전송하지 않았다.

## S9 — 성과 스냅샷

- D1/D7/D28의 24시간 수집 창을 구분하며 놓친 날짜에 현재 누적치를 소급 저장하지 않는다. 게시물·플랫폼·스냅샷·지표별 결정적 ID로 중복을 막고 수기 기록을 덮어쓰지 않는다.
- 인스타는 views/reach/likes/comments/saved/shares/total_interactions, Threads는 views/likes/replies/reposts/quotes/shares만 수집한다. 지원하지 않거나 누락된 지표는 0으로 만들지 않는다. 글타래는 첫 게시물을 비교 단위로 쓰며 답글 수치를 합산하지 않는다.
- 플랫폼·경과일·게시일·지표 필터, 중앙값/범위/n, n<5 비교 보류, 겹친 범위 차이 없음, 미연결/마지막 저장 상태를 표시한다. 기존 수기 성과 화면은 유지하고 자동 스냅샷과 혼합 합산하지 않는다. YouTube 분석은 미연결 안내다.
- 전체 verify 501개·타입·빌드 통과, 린트 오류 0. D1 소급 금지·누락과 실제 0 구분·표본 판단·고유 ID·수기 보존 시험 포함. 실제 API 수집·기한별 cron·브라우저 전체 검수는 아직 수행하지 않았다.

## S10 — 공통 화면 마무리

- 내 할 일의 매출·목표 보기를 제거하고, 오늘까지 게시 확인·답할 댓글·최근 성과 저장·채널 만료·막힌 일을 표시했다. 실패/미연결을 0으로 표시하지 않고 최근 200건 한계를 안내한다.
- 기존 검수 작업의 내 할 일 3탭, 회의 담당·기한 필수 검수, 결정 출처 필터, 업무 분류 대기·일괄 지정, 접근 키 단계·만료, 실제 연결 증거, 수정 요청 서랍을 보존했다.
- 연차는 등록된 잔여 기록의 중앙값·범위·n으로 변경했다. 외부 관리자 링크는 회사 설정에 기존 저장 형식 그대로 옮겼고 목표 화면 링크를 제거했다.
- 서버 상태는 기존 1개 조회를 재사용해 설정 묶음에 실패 점을 표시한다. 댓글에도 공정 상단의 선택 영상 범위를 적용했다.
- React 검토 지침에 따라 독립 조회는 병렬로 수행하고, 중복 상태 조회·언마운트 후 요약 반영을 방지했다.
- 전체 verify: 503개 통과, 타입·빌드 통과, 린트 오류 0(로컬 이미지 미리보기 경고 1). 실제 계정/DB·운영 데이터 검증은 수행하지 않았다.
