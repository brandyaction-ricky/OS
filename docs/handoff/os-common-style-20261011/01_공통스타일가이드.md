## 1. 한 줄 요약

**우선순위는 선택자 길이가 아니라 레이어로 정한다.** 지금 CSS는 그대로 '옛 층'에 넣고, 공통 부품은 '키트 층', 메뉴 화면은 '화면 층'에 둔다. 뒤 층이 항상 이긴다.

- [확인] 지금은 새 CSS가 옛 CSS를 이기려고 선택자를 계속 길게 만든다: 옛 `0,1,0` → 키트 `0,3,0` → 화면 `0,4,0`~`0,5,0` → 재무는 id 선택자 `1,3,0`까지.
- [확인] 그래도 지는 곳이 있다. 레이어로 바꿔 보니 화면 파일이 원한 값이 키트·옛 규칙에 막혀 있던 요소가 54곳 나왔다 (02_현황진단 4장).

## 2. 원칙 8가지

1. **색은 `app/theme-tokens.css` 토큰만.** hex · rgba · white/black 금지. 메뉴만의 색 토큰(`--kw-*`, `--hr-*`)을 새로 만들지 않는다.
2. **테마별 규칙 금지.** `html[data-theme=…]` · `[data-theme=dark] .x` 를 쓰지 않는다. 토큰이 두 테마를 바꿔 준다.
3. **값은 정해진 단계에서만.** 글자 · 간격 · 둥글기 · 높이 · 끊는 점은 4장 표의 값만 쓴다.
4. **부품은 키트 먼저.** 단추 · 입력 · 배지 · 분절 · 탭 · 패널 · 표 · 지표 · 빈 상태 · 서랍 · 창은 키트 클래스를 쓴다. 메뉴 파일에서 키트 부품의 크기 · 색 · 여백을 다시 정하지 않는다.
5. **메뉴 CSS는 자기 접두어만.** 화면 파일의 새 클래스는 그 메뉴 접두어(`tm-` · `ca-` · `hr-` …)로만 만든다 (7장).
6. **요소 선택자로 모양 정하지 않기.** 화면 파일에서 `button` · `input` · `h1` · `p` · `a` 처럼 태그 이름으로 모양을 정하지 않는다. 클래스를 붙인다.
7. **글자 11px 이상, 대비 4.5:1 이상, 상태는 색 + 글자.**
8. **`!important` · id 선택자 · 인라인 `style` 금지.** 계산값(막대 너비 `%` 등)만 인라인 허용.

## 3. 레이어 구조

### 3.1 순서

```css
@layer os.vendor, os.base, os.legacy, os.kit, os.screen;
```

| 층 | 들어가는 것 | 성격 |
|---|---|---|
| (레이어 밖) | `app/theme-tokens.css` | 색 토큰. 어떤 층도 덮지 못한다 |
| `os.vendor` | 패키지 CSS (비어 있음 — 편집기 CSS는 D2 결정 전까지 `os.legacy`) | 가장 약함 |
| `os.base` | `os-foundation.css` 의 토큰 · 브라우저 기본값 보정 | 어떤 OS 규칙에도 진다 |
| `os.legacy` | 지금 CSS 대부분 (`globals.css` 등 13개) | 고치지 않고 감싸기만 |
| `os.kit` | `os-ui.css` · `fullscreen-*.css` 4개 · `os-foundation.css` 부품 | 공통 부품 |
| `os.screen` | 메뉴 화면 파일 7개 | 메뉴 전용. 가장 셈 |

파일별 배정 표는 `tests/os-css-architecture.test.mjs` 의 `FILE_LAYER` 가 정답이다.

### 3.2 왜 이렇게 나눴나

- [확인] 키트 파일을 무조건 위로 올리면(시험 P1) 52개 메뉴 전부에서 사이드바가 바뀐다(요소 7,654곳). `fullscreen-shell.css` 등 키트 뒤에 불러오는 파일이 지금 키트를 고쳐 쓰고 있기 때문이다. → 그 파일들은 키트와 같은 층에 둔다.
- [확인] 개발 메뉴 CSS(`development-workspace.css`)를 화면 층에 두면(시험 P2) 화면 제목이 22px → 25px로 돌아간다. 10/3 통일 전 값이다. → 키트보다 오래된 메뉴 파일은 옛 층에 둔다.
- 화면 층에는 10/3 키트 이후 기획·개발한 메뉴 파일만 둔다: 팀 · 콘텐츠 자동화 · AI 작업 화면 · 인사 · 재무 · 문서 보관함 · 회사 문서.

### 3.3 꼭 지킬 것

- **모든 CSS 파일 첫 줄에 같은 순서 문장.** Next는 화면을 옮길 때 CSS 조각을 나중에 붙인다. 순서 문장이 한 파일에만 있으면, 먼저 도착한 조각이 순서를 정해 버린다.
  - [확인] 운영에서 /home → /finance/sales → /home 으로 옮기면 재무 CSS 조각이 /home 에 그대로 남는다 (2026-10-11).
- **`@import … layer()` 쓰지 않기.** [확인] Next 15.5.2 빌드가 `@media layer(os.legacy){…}` 로 바꿔서 규칙이 아예 안 먹는다. 파일 안에서 `@layer 이름 { … }` 로 감싼다.
- **레이어 밖 CSS 를 만들지 않기.** 레이어 밖 규칙은 모든 레이어를 이긴다. 패키지 CSS도 사본을 만들어 감싼다 (`components/vendor/`).
- **`!important` 는 층 순서가 거꾸로다.** 앞 층의 `!important` 가 뒤 층의 `!important` 를 이긴다.
  - [확인] 보관함 편집기: `globals.css:1038` 의 `padding … !important` 가 `knowledge-vault.css:280` 의 `!important` 를 이겨서 여백이 바뀐다.
  - → 옛 파일과 화면 파일이 서로 `!important` 로 싸우던 곳은 **둘 다 지운다**. 층이 순서를 정해 준다.

## 5. 상태 배지 — 한 가지로

모양은 키트 `.status-pill` 하나. 색은 `data-tone` 8가지. 메뉴마다 따로 만든 배지(`.ca-v07-status` · `.hr-pill` · `.kw-badge` · `.dev-status-*` · 재무 `.pill`)는 이것으로 바꾼다.

| `data-tone` | 글자 / 바탕 | 뜻 |
|---|---|---|
| `neutral` | `--text-2` / `--panel-3` | 아직 시작 전 |
| `progress` | `--accent-2` / `--accent-soft` | 진행 중 |
| `info` | `--cyan` / `--cyan-soft` | 예정 · 예약 |
| `wait` | `--purple` / `--purple-soft` | 남이 볼 차례 · 결과 도착 |
| `warn` | `--warning` / `--warning-soft` | 확인 필요 |
| `ok` | `--mint` / `--mint-soft` | 끝남 · 승인 |
| `danger` | `--danger` / `--danger-soft` | 막힘 · 실패 · 반려 |
| `muted` | `--muted` / `--panel-3` | 취소 · 삭제 · 지난 것 |

- [확인] 8짝 모두 다크·라이트에서 대비 4.5:1 이상 (팀 메뉴 검사와 같은 계산).
- 지금 `data-status` 값(draft · review · approved · scheduled · waiting · published · failed · manual)은 그대로 동작한다. 새 화면만 `data-tone` 을 쓴다.

**메뉴별 대응표** (화면 이름 → `data-tone`)

| 메뉴 | neutral | progress | info | wait | warn | ok | danger | muted |

## 8. 반응형 · 접근성

- 1100 이하: 2단 → 1단, 옆 칸 고정 끔. 820 이하: 사이드바 서랍(셸 규칙), 표·보드·주 보기는 가로로 넘김, 누름 40. 520 이하: 입력 1칸.
- 초점: 키트가 `.ui-v2 :focus-visible` 에 `2px var(--accent)` 를 그린다(`os-ui.css:422-423`). 새로 쓰지 않는다.
- 줄 전체가 눌리면 `role="link"` + `tabindex="0"` + Enter. 체크는 `role="checkbox"` + `aria-checked`.
- 색만으로 뜻을 전하지 않는다: 배지에 글자, 기한 지남은 '1일 지남'처럼 글로도.
- `prefers-reduced-motion` 이면 움직임을 끈다 (`os-foundation.css`).

## 9. 하지 말 것

- 화면 파일에 hex · rgba · white/black, `[data-theme]`, id 선택자, `!important`, 인라인 색.
- 화면 파일에서 `button{…}` `h1{…}` `p{…}` 처럼 태그로 모양 정하기 — [확인] `.linear-shell .ui-v2.ca-v07 button`(0,3,1)은 키트 `.primary-button`(0,3,0)을 이겨서 키트 단추가 안 나온다.
- 키트 부품의 크기·색을 메뉴 안에서 다시 정하기.
- 메뉴만의 색 토큰 · 다크 규칙 만들기.
- 4장 단계 밖의 글자 크기 · 둥글기 · 끊는 점.
- `@import`, 패키지 CSS 직접 import, 컴포넌트 안에서 새 전역 CSS import(새 파일은 `FILE_LAYER` 표에 먼저 적는다).
- 공용 파일(`globals.css` · `os-ui.css`)을 메뉴 하나 맞추려고 고치기.

## 10. 기획 시안을 만들 때 (이 프로젝트에서 지킬 것)

지금까지는 채팅방마다 CSS 방식이 달랐다 (콘텐츠 자동화 `.ui-v2.ca`, 팀 `.tm-root`, 재무 시안 자체 토큰). 앞으로 시안은 이렇게 만든다.

1. 시안 HTML은 **OS CSS 원본 + `os-foundation.css`** 위에서 그린다. 시안만의 색·글꼴·단추를 만들지 않는다.
2. 마크업은 6장 키트 클래스로 쓴다. 키트에 없는 것만 메뉴 접두어로 만든다.
3. 화면 CSS는 **파일 하나**로 전달한다: 첫 줄 순서 문장 + `@layer os.screen { … }`, 7장 접두어.
4. 그 파일과 검사(`os-css-architecture` 규칙)를 시안 안에서 먼저 통과시킨다.
5. 시안 전용 조작 막대 · 노트는 `<style id="prototype-only">` 로 따로 두고 전달하지 않는다.
6. [확인] 팀 메뉴는 이 방식(파일 그대로 + 검사)으로 전달해 CSS가 1줄만 바뀌고 그대로 반영됐다(`components/team-workspace.css`). 콘텐츠 자동화 v0.7은 전달한 CSS가 쓰이지 않고 새로 작성됐다(키트 클래스 사용 0곳).
