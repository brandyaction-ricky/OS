- 기준 커밋: `brandyaction-ricky/OS` main `f5bffd6` (= 10/31 운영 배포). 줄 번호는 이 커밋 기준이다.
- 근거: 「브랜디 OS 스타일 점검 — 메뉴별 수정·개선 (10/31)」 1장·3장. 화면 82개를 밝게·어둡게·휴대폰으로 잰 결과다.
- 범위: CSS 12개 파일, TSX 1개(`youtube-process-links.tsx`), 새 검사 파일 1개. 화면 구조·문구·데이터·API는 바꾸지 않는다.
- 이 폴더의 `p1.patch`가 아래 표를 그대로 구현한 것이다. 별도 작업 공간에서 적용하고 검사·재측정을 마쳤다(4장). 저장소에 커밋하지는 않았다.

---

## 1. 지킬 것

1. **원래 줄을 고친다.** 파일 끝이나 다른 파일에 덮어쓰는 규칙을 더하지 않는다. 지금 `youtube-process.css`는 같은 선택자를 48번 다시 정의한다. 이런 덮어쓰기가 계속 어긋나는 원인이다.
2. **색은 `app/theme-tokens.css` 토큰만 쓴다.** hex·rgb·white·black을 쓰지 않는다. 없는 변수에 기대는 대체값(`var(--surface,#fff)`)도 쓰지 않는다.
3. **글자색으로 `--accent`를 쓰지 않는다.** 글자 강조색은 `--accent-2`다. 어두운 테마의 `--accent`(#716879)는 단추 바탕용이라 글자로 쓰면 3.41:1밖에 안 된다.
4. **상태색(`--danger`·`--mint`·`--warning`·`--cyan`·`--purple`)으로 바탕을 칠하면 그 위 글자는 `var(--bg)`다.** 흰 글자를 올리면 어두운 테마에서 2.35:1이다.
5. **글자는 11px 이상, 누를 곳은 24px 이상이다.** 휴대폰 너비(820px 이하)에서는 40px이다.
6. `tests/os-style-p1.test.mjs`가 1~5를 검사한다. 이 검사는 끄거나 예외를 늘리지 않는다.

2. `node --test tests/os-style-p1.test.mjs` → 6개 통과.
3. `npm test` → `tests/shortform-diagrams.test.mjs`의 "portrait animation…" 1개를 뺀 나머지 통과. 이 1개는 패치 전 `f5bffd6`에서도 같은 오류(`SHORTFORM_RENDER_FAILED`, 렌더러 환경)로 실패한다. 패치와 무관하다.
