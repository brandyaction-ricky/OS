# Longform Pilot 운영 가이드

## 목적

첫 Pilot은 자동화 성능을 확인하는 테스트가 아니다. 실제 팀원이 Pull → Work → Push → Handoff를 이해하고, 상태와 최신 버전이 정확하게 이어지는지 확인하는 테스트다.

## Pilot 범위

- 실제 롱폼 콘텐츠 1건
- 최소 2명의 서로 다른 컴퓨터
- 기획부터 게시 또는 성과 회수까지
- 대용량 자산은 외부 스토리지에 보관하고 Markdown에는 식별 정보만 기록

## 시작 전 확인

- [ ] GitHub 저장소가 Private이다.
- [ ] 참여자가 저장소 접근 권한을 갖고 있다.
- [ ] 모든 참여자가 `./setup.sh 작업자명`을 실행했다.
- [ ] 모든 참여자의 `ba doctor`가 정상이다.
- [ ] 단계별 담당자와 최종 승인자가 정해졌다.
- [ ] API Key, 비밀번호, 고객 개인정보를 Markdown에 기록하지 않는다.

## 성공 조건

- [ ] 두 번째 컴퓨터에서 첫 번째 작업자의 최신 Push가 보인다.
- [ ] Pull 이후 원격이 변경되면 오래된 Push가 차단된다.
- [ ] 산출물이 `v1 → v2` 형태로 누적된다.
- [ ] `CONTENT.md`의 현재 단계, 담당자, 다음 행동이 일치한다.
- [ ] 승인 대기와 승인 완료가 구분된다.
- [ ] 다음 단계가 완료 전에는 잠겨 있다.
- [ ] `ba validate`와 GitHub Actions가 모두 통과한다.

## Pilot 중 기록할 문제

문제가 생기면 아래 항목만 기록한다.

```text
사용자:
Content ID:
실행한 명령:
기대한 결과:
실제 결과:
오류 메시지:
작업이 멈춘 시간:
```

Pilot 완료 후 반복된 문제만 CLI 또는 웹 UI 기능으로 이전한다.
