# 직원 구독 AI로 이미지 광고 작업 받기

이미 연결한 영상 제작용 Claude·Codex가 OS에서 직원 작업을 가져간다면 같은 대기열에서 이미지 광고도 처리한다. 상품을 고른 직원은 소구점을 직접 입력하고 레퍼런스를 선택한다. 카피 단계에서 구독 AI에 제목·본문·버튼 문구 초안을 요청할 수 있다. 기존 프로젝트에 저장된 소구점 후보는 다시 열어 사용할 수 있다.

개인 Mac에서 계속 받으려면 작업 화면의 **AI 연결 확인**에서 실행 파일을 받는다. 기존에 로그인한 Codex와 Brandy OS MCP 연결을 사용하는 직원은 다음 명령으로 수신기를 켠다.

```sh
node ~/Downloads/image-ad-subscription.mjs --codex
```

Mac에서는 설치된 데스크톱 앱의 Codex를 먼저 확인한다. 본인 Codex에 설정한 구독 모델을 지원하는 버전이 필요하다.

특정 요청 한 건만 처리하려면 명령 끝에 `--once --job 작업ID`를 붙인다. 수신기를 켠 터미널을 닫으면 다음 요청은 대기 상태로 남는다.

Claude Code 구독을 사용하는 직원은 아래 명령으로 시작한 뒤 직원 본인의 기존 OS MCP 연결 주소를 입력한다. 계정과 연결 정보는 [내 AI 연결 설정](https://brandyaction-os.vercel.app/settings/access)에서 확인한다.

```sh
node ~/Downloads/image-ad-subscription.mjs
```

- Node.js 22 이상을 사용한다. Claude를 선택하면 Claude Code 2.1.321 이상 2.x가 필요하다. 실행기는 PATH와 Mac용 Claude Desktop에 딸려온 Claude Code 순서로 확인한다. 다른 위치에 설치되어 있으면 `IMAGE_AD_CLAUDE_BIN`으로 경로를 지정한다.
- Claude Code에서 기존 연결이 헤더 인증 방식이면 주소의 조직 식별자를 유지하고 자격 관리 도구에서 기존 토큰을 `BRANDY_OS_MCP_BEARER`로 제공한다. 이 변수와 OS 연결 주소는 모델 프로세스로 전달하지 않는다.
- 켜져 있는 동안 30초마다 본인의 이미지 광고 대기열을 읽는다. 요청이 있을 때만 구독 모델이 작업한다. 한 번만 확인하려면 명령 끝에 `--once`를 붙인다. Ctrl+C 또는 창 닫기로 종료한다.
- 직원은 OS에서 기획을 입력하고 추천 이미지와 카피를 검토한다. 카피에 쓸 사진은 포맷 승인 단계에서 선택한다. 표시되는 예시 사진은 직원 자료로 등록되지 않는다.
- 구독 로그인이 없거나 모델이 이용 한도에 도달하면 실행기가 멈춘다. 로그인 전에 시작한 실행기는 직원 작업을 수령하지 않는다. 입력 형식 오류는 한 번 수정해 제출한다. 결과 전송 여부가 불명확하면 화면에서 작업 상태를 확인한다.

## 포맷 승인을 마치고 공통 원본을 준비할 때

새 작업은 레퍼런스의 구성과 문구 자리를 재사용한다. A/B에서는 같은 레퍼런스와 원본을 소구점마다 유지한다. 이미지가 필요한 레퍼런스는 쓸 수 있는 프로젝트 원본을 확인한다. **실제 결과 화면**에는 공개 가능한 실제 원본을 사용한다. 제목·본문·버튼은 OS에서 따로 얹는다. 이전에 장면을 기획한 작업은 저장된 컨셉과 장면을 계속 사용한다.

새 원본이 필요한 요청은 OS에 연결된 직원 본인의 **이미지 생성이 가능한 Codex 구독 세션**에서 작업한다. 이미 같은 세션에서 직원 작업을 자동 수신하는 경우 해당 대기열을 사용한다. 자동 수신을 사용하지 않는 직원은 작업 화면에서 해당 작업의 요청문을 복사해 연결된 Codex 채팅에 보낸다. 다운로드한 수신기는 글 작업을 처리한다. 원본 제작은 이미지 생성이 가능한 구독 세션이 맡는다. 이미 사진을 선택했다면 평소처럼 카피만 받을 수 있다.

Codex는 직원 키로 해당 작업을 수령하고 내장 이미지 생성으로 글자 없는 PNG/JPEG를 만든다. `image_creative_asset`의 `prepare`로 받은 주소에 결과 파일을 올리고 `commit`이 확인한 경로와 크기로 결과를 제출한다. 같은 작업을 다시 수령하면 이미 등록한 원본을 재사용한다. 원본 미등록·다른 작업 원본·소구별로 서로 다른 사진을 제출하면 승인 대기 단계로 넘어가지 않는다. 구독 앱에 이미지 생성 또는 기존 OS 연결이 없으면 작업을 수행할 수 없는 이유를 남긴다.

소구점 비교는 전 후보에 같은 원본과 CTA를 쓴다. 카피 테스트에서는 승리 소재의 원본·소구·구도와 변경하기로 한 문구 이외의 내용을 보존한다. 이미지 테스트에서는 승리 소재의 문구와 구도를 유지하며 사진을 바꾼다. 담당자가 미리보기를 확인한 다음 선택한 맥에서 최종 PNG를 출력한다.

## 실제 OS 화면을 로컬에서 검토하기

`tools/dev-image-direction.mjs`는 이 저장소의 Next 개발 서버에서 `/content/images`를 연다. 상품·타겟·포맷 창고는 직원이 기존에 연결한 Brandy OS MCP로 원문을 읽는다. 조회에는 모델을 호출하지 않는다. 예전에 내보낸 상품 파일을 인자로 주더라도 문서 위치만 사용하며 이전 본문이나 버전은 사용하지 않는다. Node 24와 MCP 직접 호출을 지원하는 Codex 앱 CLI가 필요하다. `IMAGE_AD_OPERATING_DOC`에는 운영 정본 문서 ID를 지정한다. AI 기획을 요청할 때는 기존 ChatGPT 구독 로그인이 필요하다. `CODEX_APP_RUNTIME_CLI_PATH`가 있으면 데스크톱 앱의 CLI를 사용한다.

```sh
node tools/dev-image-direction.mjs
```

개발 맥에서 처음 연결할 때는 `IMAGE_AD_CHANNEL_DOC`(마이인 상품 운영 정본), `IMAGE_AD_AUDIENCE_DOC`(핵심 타겟 정본), `IMAGE_AD_WAREHOUSE_DOC`(포맷 창고 목차)에 해당 문서 ID를 설정한다. 별도 상품 목록을 쓰면 `IMAGE_AD_PRODUCT_LIST_DOC`도 설정한다. ID가 없으면 제목으로 찾지만 OS 검색 결과만으로 원문을 특정하지 못할 수 있다. 이때 이전 상품을 표시하지 않는다.

같은 맥에서 http://127.0.0.1:3491/content/images 를 연다. 상품을 고른 뒤 소구점을 직접 작성한다. 레퍼런스를 선택한 뒤 카피를 작성한다. 개발용 구독 실행기도 연결된 OS와 같은 카피 요청문, 레퍼런스 목록, 입력 검증을 쓴다. 로컬에서는 프로젝트를 브라우저에 저장한다. 배포된 OS에서는 인증한 직원의 프로젝트와 구독 AI 대기열에 저장한다. 로컬 구독 실행 경로는 배포 빌드에 들어가지 않는다.
