# 직원 구독 AI로 이미지 광고 작업 받기

이미 연결한 영상 제작용 Claude·Codex가 OS에서 직원 작업을 가져간다면 같은 대기열에서 이미지 광고도 처리한다. 새 단독 광고와 A/B 프로젝트에서 직원이 소구점 추천을 요청할 때만 타겟과 제공 내용을 바탕으로 구독 AI가 소구점을 제안한다. 직접 작성하면 이 단계에서는 AI 작업이 생기지 않는다. 직원이 고른 디자인 레퍼런스와 소구점을 카피 작성에 사용한다.

별도 수신이 필요한 직원은 개인 Mac에서 현재 실행기를 켜 둔다. 기존에 컨셉과 장면으로 시작한 프로젝트의 기획 작업도 이어서 처리한다. 처음 한 번 받은 **본인 OS MCP 연결 주소**와 **Claude Code에 로그인된 Claude 구독**이 필요하다. 연결 상태는 [내 AI 연결 설정](https://brandyaction-os.vercel.app/settings/access)에서 확인한다. Claude Desktop의 로그인과 Claude Code의 구독 로그인은 다를 수 있다.

OS에서 **AI 연결 확인 → Claude 구독으로 자동 수신 · 실행 파일 받기**를 눌러 [실행 파일](https://brandyaction-os.vercel.app/myin-local/image-ad-subscription.mjs)을 다운로드한다. Mac 터미널에 아래 한 줄을 붙여 넣고 직원 본인의 기존 OS 연결 주소를 입력한다. 화면과 명령 기록에 주소가 표시되지 않는다.

```zsh
node ~/Downloads/image-ad-subscription.mjs
```

- Node.js 22 이상, Claude Code 2.1.321 이상 2.x를 사용한다. 실행기는 PATH와 Mac용 Claude Desktop에 딸려온 Claude Code 순서로 확인한다. 다른 위치에 설치되어 있으면 `IMAGE_AD_CLAUDE_BIN`으로 경로를 지정한다.
- 기존 연결이 헤더 인증 방식이면 주소의 조직 식별자를 유지하고 자격 관리 도구에서 기존 토큰을 `BRANDY_OS_MCP_BEARER`로 제공한다. 이 변수와 OS 연결 주소는 모델 프로세스로 전달하지 않는다.
- 켜져 있는 동안 30초마다 본인의 이미지 광고 대기열을 읽는다. 요청이 있을 때만 구독 모델이 작업한다. 한 번만 확인하려면 명령 끝에 `--once`를 붙인다. Ctrl+C 또는 창 닫기로 종료한다.
- 직원은 OS에서 기획을 입력하고 추천 이미지와 카피를 검토한다. 카피에 쓸 사진은 포맷 승인 단계에서 선택한다. 표시되는 예시 사진은 직원 자료로 등록되지 않는다.
- 구독 로그인이 없거나 모델이 이용 한도에 도달하면 실행기가 멈춘다. 로그인 전에 시작한 실행기는 직원 작업을 수령하지 않는다. 입력 형식 오류는 한 번 수정해 제출한다. 결과 전송 여부가 불명확하면 화면에서 작업 상태를 확인한다.

## 포맷 승인을 마치고 공통 원본을 준비할 때

새 작업은 레퍼런스의 구성과 문구 자리를 재사용한다. A/B에서는 같은 레퍼런스와 원본을 소구점마다 유지한다. 이미지가 필요한 레퍼런스는 쓸 수 있는 프로젝트 원본을 확인한다. **실제 결과 화면**에는 공개 가능한 실제 원본을 사용한다. 제목·본문·버튼은 OS에서 따로 얹는다. 이전에 장면을 기획한 작업은 저장된 컨셉과 장면을 계속 사용한다.

새 원본이 필요한 요청은 OS에 연결된 직원 본인의 **이미지 생성이 가능한 Codex 구독 세션**에서 작업한다. 이미 같은 세션에서 직원 작업을 자동 수신하는 경우 해당 대기열을 사용한다. 자동 수신을 사용하지 않는 직원은 작업 화면에서 해당 작업의 요청문을 복사해 연결된 Codex 채팅에 보낸다. 다운로드형 Claude 글 전용 실행기는 원본 제작 요청을 가져가지 않는다. 이미 사진을 선택했다면 평소처럼 카피만 받을 수 있다.

Codex는 직원 키로 해당 작업을 수령하고 내장 이미지 생성으로 글자 없는 PNG/JPEG를 만든다. `image_creative_asset`의 `prepare`로 받은 주소에 결과 파일을 올리고 `commit`이 확인한 경로와 크기로 결과를 제출한다. 같은 작업을 다시 수령하면 이미 등록한 원본을 재사용한다. 원본 미등록·다른 작업 원본·소구별로 서로 다른 사진을 제출하면 승인 대기 단계로 넘어가지 않는다. 구독 앱에 이미지 생성 또는 기존 OS 연결이 없으면 작업을 수행할 수 없는 이유를 남긴다.

소구점 비교는 전 후보에 같은 원본과 CTA를 쓴다. 카피 테스트에서는 승리 소재의 원본·소구·구도와 변경하기로 한 문구 이외의 내용을 보존한다. 이미지 테스트에서는 승리 소재의 문구와 구도를 유지하며 사진을 바꾼다. 담당자가 미리보기를 확인한 다음 선택한 맥에서 최종 PNG를 출력한다.

## 실제 OS 화면을 로컬에서 검토하기

`tools/dev-image-direction.mjs`는 이 저장소의 Next 개발 서버에서 `/content/images`를 연다. 개발용 상품 목록 파일은 읽을 수 있는 정본에서 추출한 ImageAdProduct 배열을 사용하고 저장소 밖에 둔다. Node 24, ChatGPT 구독에 로그인한 Codex CLI, 운영 정본을 읽을 수 있는 기존 Brandy OS MCP 연결이 필요하다. `IMAGE_AD_OPERATING_DOC`에는 운영 정본 문서 ID를 지정한다. `CODEX_APP_RUNTIME_CLI_PATH`가 있으면 데스크톱 앱에 포함된 CLI를 사용한다.

```sh
node tools/dev-image-direction.mjs /path/to/approved-dev-products.json
```

같은 맥에서 http://127.0.0.1:3491/content/images 를 연다. 상품을 고른 뒤 소구점을 직접 작성하거나 구독 AI에 추천을 요청한다. 레퍼런스를 선택한 뒤 카피를 작성한다. 개발용 구독 실행기도 연결된 OS와 같은 소구점·카피 요청문, 레퍼런스 목록, 입력 검증을 쓴다. 로컬에서는 프로젝트를 브라우저에 저장한다. 배포된 OS에서는 인증한 직원의 프로젝트와 구독 AI 대기열에 저장한다. 로컬 구독 실행 경로는 배포 빌드에 들어가지 않는다.
