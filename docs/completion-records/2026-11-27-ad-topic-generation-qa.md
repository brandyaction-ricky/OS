# 주제별 광고 콘텐츠 생성 QA

## 결론

가상의 도자기 수업·원두 구독·예약 관리 서비스 3개 주제로, 현재 바로 제작 가능한 디자인 5종을 실제 화면에서 제작했다. 총 15장의 1080×1350 PNG를 생성하고 3개 ZIP을 내려받았다. 15장 모두 ZIP 안의 파일과 화면 미리보기의 SHA-256이 일치하며 새로고침 후에도 동일하게 복원됐다. 도자기 시안 1장의 개별 PNG 다운로드도 일치했다.

출력 기능은 작동하지만 모든 결과를 바로 광고로 사용하기에는 입력 보존과 사진 배치 문제가 있다. **저장 전 입력이 사진 업로드로 사라지는 문제, 상품을 알아보기 어렵게 자르는 기본 사진 배치부터 개선하는 것이 우선이다.** 이번 작업은 QA와 개선점 도출이며 제품 코드를 수정하지 않았다.

이미지 소재·영상 소스의 AI 생성은 이 환경에서 완료할 수 없었다. 세 주제 각각 이미지 소재 3개, 영상 장면 3개를 요청하는 화면 흐름을 실행했으나 모두 구성 미리보기까지이며 실제 생성 수는 0개다. 이 결과를 AI 생성 성공으로 계산하지 않았다.

## 재현한 개선점

P1은 다음 실사용 전 우선 수정, P2는 사용성·결과 품질 개선이다. 운영 환경에서 재현했다고 주장하지 않으며 브라우저 관찰과 코드 확인을 구분한다.

### 코드 확인으로 좁힌 원인

- `components/image-creative-workspace.tsx`: 사진 업로드가 `applyBundle`을 호출하고, 이 함수가 같은 작업에서도 `setBrief(next.state.brief)`로 저장 전 입력을 덮어쓴다. 브라우저에서 확인한 현상과 일치한다. 운영 경로도 같은 함수를 사용하지만 운영 재현은 미수행이다.
- 같은 파일의 `approvalKey` 계산은 잘못된 요청 예외를 삼키고 빈 키로 처리한다. 사진 두 장 선택 시 원인이 화면에 전달되지 않는다.
- `lib/image-creative/format-test-renderer.mjs`: 사진 자르기 좌표가 디자인별로 고정되어 있다. `components/image-design-editor.tsx`의 편집 항목은 글꼴·카드·게재 위치·출력 해상도이며 사진 중심·확대 조절은 제공하지 않는다. 이는 코드 확인 결과다.

## 정상 동작한 부분

- 3개 작업의 브랜드·제목·본문·CTA가 각 결과와 ZIP 메타데이터에 반영됐다. 신규 작업에 앞 작업의 시안·사진이 섞이지 않았다.
- 카피 승인 전에는 결과 이미지가 노출되지 않고 다운로드가 막혔다. 최종 검수 후 다운로드할 수 있었다.
- 15개 결과가 모두 1080×1350 PNG이며 각 파일 해시가 서로 다르다.
- 세 작업을 URL로 다시 열어도 5개씩 동일한 PNG가 복원됐다.
- 세 ZIP 모두 5개 PNG와 `variants.json`을 포함하고, 디자인 순서는 M01·M09·A04·A10·D12이며 각 미리보기와 파일 해시가 일치했다.
- 영상 스크립트에서 빈 줄은 장면으로 세지 않았다. 3개의 대사와 첫 장면의 화면 설명을 구성 결과에 유지했다. 세 번째 대사만 수정했을 때 첫 장면 설명도 유지됐다.
- 예약 관리 결과 화면은 390×844에서 가로 넘침이 없었으며 5개 개별 내보내기 버튼이 활성화됐다. 모바일 전체 작업 흐름을 모두 재검사한 것은 아니다.
- 관련 모델·출력·광고 소스 테스트 27개 통과. `node --test tests/ad-source-studio.test.mjs tests/image-creative.test.mjs tests/image-warehouse-output.test.mjs`를 실행했다. 이 테스트에는 로컬 대체 응답 검증이 포함되며 실서비스 AI 호출 증거가 아니다.

## 미검증과 다음 QA 기준

현재 환경에서는 AI 호출, 결과의 브랜드 일관성·사진 사실성·한글 렌더링 정확도, DEV 저장소 업로드, 과금, 실패 후 재생성, 여러 탭에서의 생성 지속, 실제 Mac 출력까지 검증하지 못했다. 새 headless 브라우저 전체 E2E는 이전 Chromium 실행 권한 문제로 재실행하지 않았고, 이번에는 연결된 브라우저에서 위 과제를 수행했다. 제품 코드 변경이 없어 빌드·린트·타입 전체 검사를 반복하지 않았다.

실제 AI QA는 이 브랜치 코드가 연결된 승인된 DEV 로그인·스토리지·이미지 생성 환경에서 같은 입력을 사용해 진행해야 한다. 최소 완료 기준은 이미지 3개 × 3주제와 영상 장면 3개 × 3주제의 실제 파일 생성, 입력/참고 이미지 반영, 9:16 장면별 대상 일관성, 실패한 1개만 재시도, PNG·ZIP 다운로드 일치, 새로고침 후 복원이다. 환경 연결 전에는 배포 준비 완료로 판단하지 않는다.
