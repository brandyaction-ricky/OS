# 광고 소재 제작: 이미지 시안 · 스크립트 장면 소스

## 요청과 범위

기존 광고 메뉴는 상품·랜딩·기획 단계를 먼저 요구해 소재 제작의 시작점을 이해하기 어려웠다. `광고 → 내 광고` 첫 화면에 두 가지 제작 흐름을 추가했다.

| 흐름 | 입력 | 결과 |
| --- | --- | --- |
| 이미지 소재 | 참고 이미지(선택), 실제 광고 문구, 강조할 소구, 고객(선택), 비율, 수량 | 같은 메시지로 구성을 달리한 이미지 초안 1~6개 |
| 영상 소스 | 스크립트, 장면별 화면 설명(선택), 분위기(선택), 참고 이미지(선택), 비율 | 스크립트 한 줄당 이미지 1개, 최대 12장면 |

완료 기준: 두 흐름의 입력·검증·제작 API·소유자별 저장·재개·다운로드를 구현하고 로컬에서 검증한다. 실제 AI 품질과 Supabase 연결은 승인된 DEV 환경에서 추가 검증한다.

영상 결과는 편집용 장면 이미지다. MP4, 음성, 자막, 스톡 영상 검색은 이번 범위에 포함하지 않는다. 완성 광고 승인·집행은 기존 단계별 제작을 사용한다.

## 구현

- `components/ad-source-studio.tsx`, `.css`: 두 가지 시작 선택, 참고 이미지 미리보기, 장면 구성 확인, 생성 진행 상태, 개별 재시도, 남은 작업 재개, PNG/ZIP 다운로드, 최근 50개 작업 다시 열기.
- `lib/ad-source-studio.ts`: 공통 입력 계약, 모든 대사를 유지하는 장면 분리, 이미지별 생성 방향과 프롬프트.
- `lib/server/ad-source-studio.ts`, `/api/v1/content/ad-sources`: 로그인·소유권 검사, 버전 비교 저장, 생성 잠금, 이미지 업로드 및 생성.
- 기존 `os_records`의 개인 `content_package`와 기존 미디어 버킷을 사용한다. 새 테이블·마이그레이션·환경 변수는 없다.
- 이미지 생성은 기존 `drawImageBytes` 전송 함수를 호출한다. 카드뉴스 파일은 수정하지 않는다.
- 참고 이미지: 최대 3장, 장당 PNG/JPEG 3MB. 실제 파일 디코딩, 픽셀 수 제한, 업로드 본문 크기 제한을 적용한다.
- 생성은 한 장씩 요청한다. 완료한 항목에 같은 요청이 다시 들어오면 추가 생성하지 않는다. 실패는 자동 유료 재시도하지 않으며 항목당 최대 3회 시도한다.
- 동시에 같은 작업을 생성할 수 없으며, 요청 중 다른 버전으로 바뀐 결과는 반영하지 않는다. 저장 응답이 유실되면 연결 여부를 다시 확인한 후 임시 파일을 정리한다.
- ZIP은 완료된 PNG와 대사·화면 설명·파일 대응표를 포함한다. 생성물은 초안으로 표시하고 광고 승인 상태를 만들지 않는다.
- 자격 증명이 없는 데모에서는 구성만 보여주고 실제 AI 이미지 생성으로 표시하지 않는다.
- 기존 상품·기획·승인 흐름은 `단계별 광고 기획`으로 접근한다.
