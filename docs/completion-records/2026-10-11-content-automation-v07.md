## 환경과 출시 상태

GitHub 브랜치는 원격에 올라갔고 최종 커밋 `5077120`의 Vercel Preview는 READY이며 PR #166 전체 CI도 통과했다. DEV 고정 주소는 이 Preview로 전환했다. 처음에는 선행 브랜치에만 있던 HR 기능 설정이 새 브랜치에 없어 인사 메뉴가 사라지는 것을 발견했다. 새 브랜치 Preview에 선행 후보와 같은 `HR_WORKSPACE_ENABLED=true`, `OS_ENVIRONMENT=qa`, `FINANCE_TOSS_SYNC_ENABLED=false`, `CANONICAL_SYNC_ENABLED=false`를 지정했고, 새 배포에서 재확인해야 한다. DEV Supabase에는 사용자 명시 승인 후 콘텐츠 자동화 SQL 2건이 순서대로 적용됐다. 이력 버전은 `20261011003653`, `20261011003703`이다. 운영 DB·운영 앱에는 변경이 없다. DEV 적용 전 회사 문서 878건·일반 기록 90건·개인 콘텐츠 기록 0건을 확인했고, 제약 충돌 기록과 새 객체 이름 중복은 0건이었다. 적용 후 문서 건수 878건·정본 851건과 본문·소유자·폴더·상태 비교값은 적용 전과 동일했다. 새 테이블·개인 기록 정책·원자적 주제 생성 함수의 존재와 해당 함수의 service_role 전용 실행 권한도 확인했다. 최근 DEV 예약 백업을 확인했다. 선행 PR #165가 열려 있으므로 병합 순서도 유지해야 한다.

첫 DEV 마이그레이션 적용 시도는 자동 승인 검토에서 거절되어 DB 변경이 없었다. 두 SQL 파일명과 DEV 프로젝트, 제약·RLS·테이블·함수 변경 범위를 밝힌 별도 명시 승인을 받은 뒤 동일한 Supabase 마이그레이션 도구로 적용했다. 거절을 우회해 SQL 편집기·다른 API·CLI로 실행하지 않았다.

운영 사전 점검은 읽기 전용으로 수행했다. 운영 DB는 회사 문서 5,204건·일반 기록 5,344건이고, 개인 공간 기록은 0건이다. 문서 본문과 소유자·폴더·상태의 사전 비교 기준을 조회했고, 외부에 원문이나 내부 문서 식별자를 기록하지 않았다. 운영과 DEV의 과거 마이그레이션 이력이 달라 로컬 전체 마이그레이션을 운영에 일괄 적용하면 안 된다. 운영에는 DEV에 이미 있는 2026-10-10 후속 마이그레이션 5건과 이번 콘텐츠 자동화 2건만 전방 적용 후보이며, 실제 범위는 DEV 검증 후 재확정한다. 운영의 HR·문서 승인 선행 객체는 존재하고, 새 콘텐츠 자동화 객체 이름 충돌은 없다. 회사 정본 842건, 대기 중인 정본 후보는 0건이다. 사용자가 지정한 최종 등록 계정은 DEV·운영 모두 활성 운영자이며, DEV에서는 유일한 최종 등록자로 지정되어 있다. 운영은 정본 게이트 적용 시 최종 등록자 지정 전까지 새 정본 등록이 막힐 수 있으므로 적용 순서를 별도 검토해야 한다. 운영 Supabase 예약 물리 백업은 2026-10-10 19:35 UTC분까지 확인했으나 시점 복구(PITR)는 꺼져 있어 DB 변경 전 별도 복구·전방 수정 계획을 유지해야 한다. 운영 주소 `brandyaction-os.vercel.app`는 최신 `main` 빌드가 아니라 이전 배포를 가리키므로, 운영 반영에는 DB 검증·코드 병합뿐 아니라 주소 전환 및 사후 점검이 필요하다. 아직 운영 변경은 없다.

## 남은 검증과 기능 범위

1. DEV의 실제 계정 2개로 개인 기록 읽기·쓰기 차단, 직접 확인, 게시 이벤트, worker 잠금·재시도·일일 한도를 검증한다.
2. 실제 Chrome의 Claude in Chrome으로 등록→가져오기→결과 제출→종료를 1회 시험한다. AI 화면은 지시문으로 운영하므로 사람이 아닌 AI가 다른 화면으로 이동하는 것을 서버가 판별할 수 없다.
3. 수동 게시 URL만으로 외부 API의 게시물 식별자와 계정 연결을 확정할 수 없어 자동 성과·댓글 수집을 보장하지 않는다. 연결 계정·외부 ID 매칭과 실제 게시 흐름은 DEV에서 검증·보완해야 한다.
4. 스킬 버전 복원은 코드·로컬 비로그인 검증만 완료했고, 실제 DEV 계정으로 이력 조회·복원은 미검증이다. 등록 브라우저의 OS 로그인 만료 시각 기록과 근접한 예약 누락에만 보이는 진단은 코드·로컬 접근 차단 검사까지 완료했으나 실제 만료 세션에서 기록되는지는 미검증이다. 10개 화면 전 조합 캡처와 실제 키보드 QA도 남았다. 서버 CSV는 코드·로컬 검사만 완료했으며 인증된 DEV 다운로드는 미검증이다. 주제 제작 시작의 DB 트랜잭션도 DEV 적용·실행 검증이 남았다. 작업별 처리 예정(`queueInfo`)은 서버 계산과 작업 목록 표시에 추가했다. 이 PR은 DEV 완료 전 초안으로 둔다.
5. DEV 완료·사용자 확인 후 운영 DB 변경과 병합·배포는 별도 범위 승인을 받는다.

회사 OS 개발 관리에는 로컬 환경 전환 기간의 쓰기 제한에 따라 기록하지 않았다. OS 동기화는 보류한다.
