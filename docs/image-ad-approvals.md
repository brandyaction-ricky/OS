# 이미지 광고 · 메뉴, 승인 버튼과 실행 순서

## 진입 위치

OS 왼쪽 **콘텐츠 자동화 → 이미지 광고**에서 **광고 한 장 만들기** 또는 **여러 안 테스트하기**를 고른다. 1~7번 공정이 보이는 메뉴에서는 **7번 반응·성과** 바로 아래에 **이미지 광고**가 별도 항목으로 있다. 여러 안 테스트하기를 누르면 A/B 테스트 프로젝트 목록이 열린다. 기존 `/content/images` 및 프로젝트별 링크에서도 같은 작업을 이어갈 수 있다.

일반 작업의 승인 단위는 화면에 표시되는 **시안 묶음 전체**다. 예를 들어 5장을 요청하면 제목·본문·CTA 다섯 벌을 함께 승인하고, 미리보기 다섯 장과 최종 출력 다섯 장을 각각 확인한다.

## 이미지 광고 만들기

단독 광고와 A/B 프로젝트는 같은 여섯 단계로 시작한다. A/B 프로젝트는 시험할 소구점을 여러 개 선택한다.

| 단계 | 직원이 하는 일 |
|---|---|
| 상품 선택 | 상품을 고르면 OS 정본의 타겟과 제공 내용을 불러온다. |
| 소구점 선택 | 구독 AI에서 추천받고 쓸 항목을 고르거나 직접 작성한다. 광고 한 장은 한 가지, A/B는 선택한 소구점마다 한 장씩 만든다. |
| 레퍼런스 선택 | 등록된 광고 디자인을 이미지로 비교하고 하나를 고른다. 직원이 고른 레퍼런스의 레이아웃과 문구 자리를 사용한다. 사진이 필요한 디자인에는 프로젝트 원본을 연결한다. |
| 카피 작성 | 선택한 소구점에 맞춰 제목·본문·버튼 문구를 작성하고 확인한다. A/B에서는 레퍼런스·원본·규격·CTA를 공통으로 유지한다. |
| 디자인 수정 | 내 문구가 적용된 미리보기를 확인한다. 필요한 경우 서체, 카드 처리, 크기를 조정한다. |
| 확정 | 미리보기를 확인하고 출력할 Mac을 고른다. 나온 PNG를 최종 확인하면 내보내기가 열린다. |

정본의 버전과 선택한 소구점·레퍼런스를 작업에 기록한다. 기존에 컨셉과 장면으로 기획했거나 이미 승인한 프로젝트는 저장된 단계에서 이어간다.

## 광고 결과로 다음 테스트 이어가기

**여러 안 테스트하기**에서 A/B 테스트 프로젝트 목록을 연다. 집행 후 같은 프로젝트를 다시 열면 현재 단계와 앞서 선택한 승리 소재를 확인할 수 있다. 집행 결과는 담당자가 확인해 입력한다.

| 결과가 나온 단계 | 직원이 하는 일 | 다음 테스트에서 고정하는 내용 |
|---|---|---|
| 소구점 | 실제로 돌린 후보 중 승리 소재를 지정하고 **카피 테스트 시작**을 누른다. | 승리 소재의 소구점, 이미지, 포맷, 크기, 디자인을 유지한다. 선택한 카피 칸만 바꾼다. |
| 카피 | 새 카피와 기존 승리 소재를 비교해 승자를 지정하고 **이미지 테스트 시작**을 누른다. | 해당 승자의 소구점, 제목, 본문, CTA와 포맷을 유지하고 이미지를 바꾼다. |
| 이미지 | 새 이미지와 기존 승리 소재 중 최종 승자를 기록한다. | 같은 프로젝트에서 각 단계의 후보와 승리 소재를 다시 볼 수 있다. |

기존 승리 소재의 성과가 새 후보보다 좋았다면 **기존 소재 승리로 기록**한다. 이때 다음 단계는 원래 승리한 소재를 그대로 사용한다. 제작을 최종 검수한 것만으로 성과 승자가 지정되지는 않는다.

집행 판단 근거는 **집행 결과 메모 (선택)**에 남길 수 있다. 이미지 테스트의 **이미지 후보 N개 만들기**는 선택한 프로젝트 사진을 한 장씩 적용해 후보를 즉시 만든다. 카피 확인, 미리보기, Mac 출력과 최종 검수를 차례로 진행한다.

## 담당자 화면과 버튼

카드에 표시하는 디자인 견본과 실제 제작에 같은 렌더러를 사용한다. **카피 작성하기**를 누르면 선택한 레퍼런스와 공통 이미지 조건을 기록한다. 직원이 직접 카피를 쓰거나 **AI 카피 초안 받기**를 누른다. 구독 AI로 공통 원본도 만들 수 있는 요청에서는 **구독 AI로 공통 이미지와 카피 받기**가 보인다. 로컬 개발 화면의 사진형 디자인에는 사용할 파일을 올린다.

| 단계 | 담당자가 확인하는 내용 | 버튼과 저장 결과 |
|---|---|---|
| 1. 포맷 승인 | 작업 목표·퍼널·대상, 제작 방식, 선택한 포맷 구성 견본, 규격, 사진 및 후보 수를 확인한다. | 새 화면은 레퍼런스 선택을 기록하고 카피 입력 칸을 연다. **작업 도구**에서는 **포맷 승인**으로 현재 조건을 기록한다. 승인 후 **내 AI에게 맡기기**, **요청문 복사**, **결과 가져오기**, 창고 포맷용 직접 카피 입력이 열린다. 다른 조건으로 제작하려면 새 조건을 승인한다. |
| 2. 카피 승인 | 후보별 포맷·소구·제목·본문·CTA와 해당하는 브랜드명을 글로 확인한다. | 새 화면은 **카피 확정 · 디자인 수정하기**로 직원이 검토한 문구를 저장하고 디자인 시안을 연다. 이전 작업과 작업 도구에서는 카피 후보 저장 후 **카피 승인**을 누른다. 이때까지 Mac 대기열에는 출력 작업이 없다. |
| 3. 미리보기 확인 | 각 장의 사진, 카피 배치, 서체, CTA, 게재 위치별 세이프 존을 확인한다. 묶음의 미리보기가 모두 준비돼야 버튼이 활성화된다. | **이미지를 출력할 컴퓨터**에서 **공용 맥미니 / 내 Mac**을 선택한다. **미리보기 확인 · 공용 맥미니에서 최종 출력** 또는 **미리보기 확인 · 내 Mac에서 최종 출력**을 누르면 이 묶음의 확인 기록과 선택 기기의 출력 요청을 함께 저장한다. |
| 4. Mac 최종 PNG 출력 | 작업 화면에서 선택한 기기와 출력 상태를 본다. 미연결 또는 대기 중인 기기는 요청을 보관한다. | 지정된 종류의 영상 워커가 작업을 가져가 PNG를 생성한다. 개인 Mac은 본인 작업만 가져간다. OS는 모든 파일의 크기·규격·해시를 확인하고 담당자 최종 검수 대기로 넘긴다. |
| 5. 최종 검수 | 선택한 기기가 실제 올린 PNG에서 만든 검수 이미지를 전부 확인한다. 원본 비율을 유지하며 표시 폭은 최대 900px다. | **최종 검수 완료**로 현재 기기의 출력본을 승인한다. 이때 **내보내기**, **N번째 묶음 ZIP**, **기준 시안 선택**이 열린다. 원본 PNG·ZIP은 검수한 출력 묶음에서 제공한다. |

각 승인과 수정 요청은 **검토 이력**에서 단계·담당자·시각을 확인한다. 카피/미리보기/최종 검수에서 **수정 요청 → 수정 사유 → 수정 요청 보내기**로 현재 결정을 되돌릴 수 있다. 수정 사유를 기록하고 해당 단계 이후의 승인을 해제한다. 최종 검수에서 돌려보낸 묶음은 미리보기를 다시 확인하고 새로 출력해야 한다. **디자인 편집 → 수정본 저장**은 원본을 보존하는 새 묶음이다. 레퍼런스로 시작한 작업에서 서체·카드·규격만 수정하면 기존 레퍼런스와 카피 결정을 이어받아 새 디자인 미리보기부터 확인한다. 이전 미리보기와 출력 승인은 수정본에 적용하지 않는다. 이전 방식으로 시작한 작업은 해당 작업의 원래 승인 순서를 따른다.

## 제작 방식과 기존 기록

- **포맷부터 시작 / 독립 제작**은 새 요청으로 시작한다. 처음 시작하는 소구점 테스트는 승인한 포맷과 사진으로 바로 만든다. 기존 소재를 활용한 **소구점 비교 / 카피 비교 / 이미지 비교**는 최종 검수를 끝낸 시안에서 **기준 시안 선택**을 누른 뒤 새 묶음으로 시작한다. 소구점 비교는 사진·포맷·CTA를, 카피 비교는 소구·사진·포맷을, 이미지 비교는 소구·카피·포맷을 고정한다.
- **포맷 창고**에서 ‘찾을 포맷’, ‘분류’, ‘바로 제작할 수 있는 창고 포맷만 보기’로 고르고 **이 작업에 사용**을 누른다. **포맷만 비교하기**는 창고 5종을 일반 승인 흐름으로 연결한다. 과거 별도 비교 패널의 기록은 ‘이전에 저장한 포맷 비교’에서 열람한다.
- 승인 도입 전에 만든 일반 시안과 수정본은 **묶음 포맷 승인**부터 다시 검토한다. 예전 기기 작업에 승인 이력이 없으면 자동 수령·완료 대상에서 제외한다. 이미 외부로 받은 파일은 소급 회수되지 않는다.
- 로컬 체험 화면의 **미리보기 확인 · 체험 출력**은 브라우저 출력으로 순서를 체험한다. 기기 연결 검수는 검수 계정과 실제 제작 컴퓨터에서 수행한다.

## 개발 연결과 인수 조건

포맷 승인은 저장된 브리프와 정규화한 요청(방식·수량·포맷·버전·규격·사진·기준 시안·카피 변경 칸)에 묶인다. 서버는 현재 작업 소유자의 로그인과 프로젝트 버전을 확인한다. AI는 카피 후보를 작성·제출하고 담당자의 승인을 기록하는 경로는 사용할 수 없다.

| OS 동작 | 프로젝트 처리 |
|---|---|
| 신규 소구점 선택 | 선택적으로 `recommend-appeals`로 구독 AI에 소구점만 요청한다. `select-appeals`는 직원이 고르거나 직접 쓴 소구점과 제작 가능한 레퍼런스 목록을 프로젝트에 저장한다. |
| 레퍼런스에서 카피로 | `approve-format`으로 선택한 레퍼런스와 제작 조건을 기록한다. 기존 `import`와 `generate`에서 같은 조건으로 작성한 카피를 검증한다. |
| 작업 도구의 포맷 승인, 카피 준비 | `approve-format` → 같은 요청의 `generate` 또는 `import`. 직원 구독 AI가 원본이 필요하면 생성·등록한다. |
| 카피 확정, 시안 보기 | 신규 제작은 `confirm-reference-copy`로 각 제목·본문·공통 CTA를 검사하고 확인한 문구를 저장한다. 이전 작업은 기존 `approve-copy`로 승인한다. |
| 미리보기 확인, 출력 | `confirm-preview`에 묶음 ID와 기기를 전달한다. 확인 당시의 묶음·기기·출력 ID가 일치하는 Mac 작업만 수령·저장할 수 있다. |
| 최종 검수, 다운로드 | 실제 Mac PNG에서 검수 이미지 읽기 → `approve-final`에 묶음 ID와 출력 ID → 프로젝트의 `export`에서 원본 PNG 또는 ZIP을 받는다. |
| 수정 및 후속 | `return-review`는 단계·사유를 기록한다. `revise-design`은 새 시안을 만든다. `select`는 최종 검수한 시안을 후속 비교 기준으로 저장한다. |

화면은 `components/image-creative-workspace.tsx`, `components/image-approval-batch.tsx`와 `components/mac-review-preview.tsx`를 사용한다. 승인 기록은 `lib/image-creative/model.ts`, 서버의 승인·다운로드 조건은 `lib/server/image-creatives.ts`, 실제 Mac의 작업 수령·완료·파일 영수증 검사는 `lib/server/image-mac-render.ts`가 담당한다.

개발자 검수에서는 승인 단계를 하나씩 건너뛴 요청, 미리보기 승인 전의 기기 작업 조회, 출력보다 앞선 최종 검수, 최종 검수 전 개별 PNG·ZIP 요청을 직접 보낸다. 모든 단계가 끝난 뒤 저장된 승인 기록과 실제 파일을 다시 연다. 수정·반려·재출력 중 예전 작업이 뒤늦게 완료되는 경우도 같은 방식으로 확인한다.

## 광고 상품 정본 관리

상품 선택지는 직원이 열람할 수 있는 현행 정본에서 읽습니다. 마이인 무료·정밀 진단은 광고 운영 정본의 상품 확인 표와 핵심 컨텍스트의 주력 타겟 표를 사용합니다. 무료 결과 견본은 견본 범위로 표시합니다.

추가 상품은 회사의 기존 정본 승인 절차에 따라 **이미지 광고 상품 목록** 문서의 **상품 목록** 섹션에 행으로 관리할 수 있습니다. 첫 열은 `상품 ID`이며, `브랜드`, `상품`, `타겟`, `제공 내용`을 채웁니다. `소재 목표`와 `퍼널`은 근거가 있을 때 추가합니다. 상품 ID는 영문·숫자·밑줄·하이픈 1~48자로 정하고, 문구를 고칠 때도 같은 값을 유지합니다. 화면과 승인 요청은 이 ID, 원문 문서와 버전을 함께 사용합니다.

```markdown
## 상품 목록

| 상품 ID | 브랜드 | 상품 | 타겟 | 제공 내용 | 소재 목표 | 퍼널 |
|---|---|---|---|---|---|---|
| sample-class | 예시공방 | 첫 만들기 수업 | 공예를 처음 배우는 사람 | 1회 체험 수업 | 체험 신청 | 첫 방문 |
```

표는 문서 본문에 일반 표로 넣습니다. 코드 블록으로 남긴 예시, 개인 초안, 중복 ID와 필수 값이 빠진 행은 선택지에 표시되지 않습니다.
