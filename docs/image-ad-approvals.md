# 이미지 광고 · 메뉴, 승인 버튼과 실행 순서

## 진입 위치

OS 왼쪽 **콘텐츠 제작 → 광고 → 이미지 광고**를 누르면 `/content/images`의 ‘이미지 광고 만들기’가 열린다. ‘이미지 광고’는 ‘내 광고 영상’ 바로 다음에 있는 같은 깊이의 메뉴다. 구형 사이드바에서는 **콘텐츠 제작 → 유튜브 공정 → 이미지 광고**에 자리한다. 담당자는 자신의 프로젝트를 생성하거나 다시 연다.

일반 작업의 승인 단위는 화면에 표시되는 **시안 묶음 전체**다. 예를 들어 5장을 요청하면 제목·본문·CTA 다섯 벌을 함께 승인하고, 미리보기 다섯 장과 최종 출력 다섯 장을 각각 확인한다.

## 담당자 화면과 버튼

| 단계 | 담당자가 확인하는 내용 | 버튼과 저장 결과 |
|---|---|---|
| 1. 포맷 승인 | 작업 목표·퍼널·대상, 제작 방식, 선택한 포맷 구성 견본, 규격, 사진 및 후보 수를 확인한다. | **포맷 승인**으로 현재 조건을 기록한다. 이 조건일 때 **내 AI에게 맡기기**, **요청문 복사**, **결과 가져오기**, 창고 포맷용 직접 카피 입력이 열린다. 다른 조건으로 제작하려면 새 조건을 승인한다. |
| 2. 카피 승인 | 후보별 포맷·소구·제목·본문·CTA와 해당하는 브랜드명을 글로 확인한다. | 직접 입력의 **선택한 포맷 N장 카피 저장**, 구독 AI 제출 또는 **결과 가져오기**는 카피 후보만 저장한다. **카피 승인** 후 실제 광고 미리보기를 연다. 이때까지 Mac 대기열에는 출력 작업이 없다. |
| 3. 미리보기 확인 | 각 장의 사진, 카피 배치, 서체, CTA, 게재 위치별 세이프 존을 확인한다. 묶음의 미리보기가 모두 준비돼야 버튼이 활성화된다. | **이미지를 출력할 컴퓨터**에서 **공용 맥미니 / 내 Mac**을 선택한다. **미리보기 확인 · 공용 맥미니에서 최종 출력** 또는 **미리보기 확인 · 내 Mac에서 최종 출력**을 누르면 이 묶음의 확인 기록과 선택 기기의 출력 요청을 함께 저장한다. |
| 4. Mac 최종 PNG 출력 | 작업 화면에서 선택한 기기와 출력 상태를 본다. 미연결 또는 대기 중인 기기는 요청을 보관한다. | 지정된 종류의 영상 워커가 작업을 가져가 PNG를 생성한다. 개인 Mac은 본인 작업만 가져간다. OS는 모든 파일의 크기·규격·해시를 확인하고 담당자 최종 검수 대기로 넘긴다. |
| 5. 최종 검수 | 선택한 기기가 실제 올린 PNG에서 만든 검수 이미지를 전부 확인한다. 원본 비율을 유지하며 표시 폭은 최대 900px다. | **최종 검수 완료**로 현재 기기의 출력본을 승인한다. 이때 **내보내기**, **N번째 묶음 ZIP**, **기준 시안 선택**이 열린다. 원본 PNG·ZIP은 검수한 출력 묶음에서 제공한다. |

각 승인과 수정 요청은 **검토 이력**에서 단계·담당자·시각을 확인한다. 카피/미리보기/최종 검수에서 **수정 요청 → 수정 사유 → 수정 요청 보내기**로 현재 결정을 되돌릴 수 있다. 수정 사유를 기록하고 해당 단계 이후의 승인을 해제한다. 최종 검수에서 돌려보낸 묶음은 미리보기를 다시 확인하고 새로 출력해야 한다. **디자인 편집 → 수정본 저장**은 원본을 보존하는 새 묶음이다. 새 묶음의 포맷·카피와 변경한 구성을 다시 확인한다.

## 제작 방식과 기존 기록

- **포맷부터 시작 / 독립 제작**은 새 요청으로 시작한다. **소구점 비교 / 카피 비교 / 이미지 비교**는 최종 검수를 끝낸 시안에서 **기준 시안 선택**을 누른 뒤 새 묶음으로 시작한다. 소구점 비교는 사진·포맷·CTA를, 카피 비교는 소구·사진·포맷을, 이미지 비교는 소구·카피·포맷을 고정한다.
- **포맷 창고**에서 ‘찾을 포맷’, ‘분류’, ‘바로 제작할 수 있는 창고 포맷만 보기’로 고르고 **이 작업에 사용**을 누른다. **포맷만 비교하기**는 창고 5종을 일반 승인 흐름으로 연결한다. 과거 별도 비교 패널의 기록은 ‘이전에 저장한 포맷 비교’에서 열람한다.
- 승인 도입 전에 만든 일반 시안과 수정본은 **묶음 포맷 승인**부터 다시 검토한다. 예전 기기 작업에 승인 이력이 없으면 자동 수령·완료 대상에서 제외한다. 이미 외부로 받은 파일은 소급 회수되지 않는다.
- 로컬 체험 화면의 **미리보기 확인 · 체험 출력**은 브라우저 출력으로 순서를 체험한다. 기기 연결 검수는 검수 계정과 실제 제작 컴퓨터에서 수행한다.

## 개발 연결과 인수 조건

포맷 승인은 저장된 브리프와 정규화한 요청(방식·수량·포맷·버전·규격·사진·기준 시안·카피 변경 칸)에 묶인다. 서버는 현재 작업 소유자의 로그인과 프로젝트 버전을 확인한다. AI는 카피 후보를 작성·제출하고 담당자의 승인을 기록하는 경로는 사용할 수 없다.

| OS 동작 | 프로젝트 처리 |
|---|---|
| 포맷 승인, 카피 준비 | `approve-format` → 같은 요청의 `generate` 또는 `import`. 직원 구독 AI가 원본이 필요하면 생성·등록한다. |
| 카피 승인, 시안 보기 | `approve-copy` → 실제 시안 미리보기. 원본 이미지·포맷 견본 열람과 광고 시안 승인을 구분한다. |
| 미리보기 확인, 출력 | `confirm-preview`에 묶음 ID와 기기를 전달한다. 확인 당시의 묶음·기기·출력 ID가 일치하는 Mac 작업만 수령·저장할 수 있다. |
| 최종 검수, 다운로드 | 실제 Mac PNG에서 검수 이미지 읽기 → `approve-final`에 묶음 ID와 출력 ID → 프로젝트의 `export`에서 원본 PNG 또는 ZIP을 받는다. |
| 수정 및 후속 | `return-review`는 단계·사유를 기록한다. `revise-design`은 새 시안을 만든다. `select`는 최종 검수한 시안을 후속 비교 기준으로 저장한다. |

화면은 `components/image-creative-workspace.tsx`, `components/image-approval-batch.tsx`와 `components/mac-review-preview.tsx`를 사용한다. 승인 기록은 `lib/image-creative/model.ts`, 서버의 승인·다운로드 조건은 `lib/server/image-creatives.ts`, 실제 Mac의 작업 수령·완료·파일 영수증 검사는 `lib/server/image-mac-render.ts`가 담당한다.

개발자 검수에서는 승인 단계를 하나씩 건너뛴 요청, 미리보기 승인 전의 기기 작업 조회, 출력보다 앞선 최종 검수, 최종 검수 전 개별 PNG·ZIP 요청을 직접 보낸다. 모든 단계가 끝난 뒤 저장된 승인 기록과 실제 파일을 다시 연다. 수정·반려·재출력 중 예전 작업이 뒤늦게 완료되는 경우도 같은 방식으로 확인한다.
