# 팀 메뉴 v1 기능·스타일 검증 기록

## 범위

- 회의·결정, 업무, 팀 일정, 팀 현황 화면에 전달된 `tm-*` 스타일을 적용했다.
- 기존 회의 엔진을 감싼 추가형 팀 명령 마이그레이션을 **파일로만** 준비했다. 기존 회사 문서의 본문, 소유자, 폴더, 상태를 변경하는 SQL은 없다.
- 회의 작성·시작·전사·요약·검수·확정, 결정 변경·폐기, 이전 회의 수동 병합, 업무 보드·분류·댓글, 인사 승인 휴가의 부재 표시를 연결했다.
- 다른 메뉴의 화면 구조는 변경하지 않았다. 팀 화면에 필요한 공용 읽기 API는 필드 또는 기간 필터만 추가했다.

## 확인한 것

- TypeScript, ESLint, 786개 단위 테스트, Next.js 프로덕션 빌드 통과. ESLint에는 기존 콘텐츠 화면의 이미지 경고 1건이 남는다.
- `TEAM_V1_ENABLED=true` 로컬 브라우저에서 8개 팀 화면을 1440/390px과 다크/라이트로 확인했다. 총 32개 이미지는 `screens/`에 있다. 페이지 바깥 가로 넘침과 브라우저 오류가 없었다.
- 전체 브라우저 회귀 검사는 153건 통과·12건 조건부 건너뜀·2건 시간 초과였다. 검사 중 개발 서버 재컴파일 화면이 보였던 두 시간 초과 케이스는 코드를 고정한 뒤 단독 재실행하여 2/2 통과했다.
- 최신 팀 전용 브라우저 검사는 옛 결정 링크와 8개 화면의 두 크기·두 테마를 포함해 5/5 통과했다.
- 댓글 API는 비로그인 또는 볼 수 없는 업무에서 쓰기를 막고, 보이는 업무에만 길이 제한된 활동 이벤트를 추가하는 단위 시험을 통과했다.

## 아직 검증하지 않은 것

- DEV·운영 DB에는 팀 마이그레이션을 적용하지 않았다. 따라서 저장·검수·병합의 실제 DB 연동, 기존 회의/업무 데이터와의 대조는 아직 하지 못했다.
- 실제 마이크 권한·녹음 장치와 전사 서비스는 브라우저 모의 화면 검사에 포함되지 않았다.
- 운영 배포는 하지 않았다. 회사 문서 데이터는 읽기/쓰기 시험에 사용하지 않았다.

## 다음 단계

1. 검토된 추가형 SQL을 확인된 DEV DB에 적용한 뒤, 전용 테스트 계정의 시험 기록으로 권한·버전 충돌·검수·부재를 확인한다.
2. Preview 화면과 실제 DEV 데이터 결과를 사용자에게 확인받는다.
3. 운영 DB 적용 SQL과 앱 릴리스 범위를 별도 확정하고, 운영 배포 승인을 받는다.
