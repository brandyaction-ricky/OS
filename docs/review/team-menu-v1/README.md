# 팀 메뉴 v1 기능·스타일 검증 기록

## 범위

- 회의·결정, 업무, 팀 일정, 팀 현황 화면에 전달된 `tm-*` 스타일을 적용했다.
- 기존 회의 엔진을 감싼 추가형 팀 명령 마이그레이션을 DEV에 적용했다. 기존 회사 문서의 본문, 소유자, 폴더, 상태를 변경하는 SQL은 없다.
- 회의 작성·시작·전사·요약·검수·확정, 결정 변경·폐기, 이전 회의 수동 병합, 업무 보드·분류·댓글, 인사 승인 휴가의 부재 표시를 연결했다.
- 다른 메뉴의 화면 구조는 변경하지 않았다. 팀 화면에 필요한 공용 읽기 API는 필드 또는 기간 필터만 추가했다.

## 확인한 것

- TypeScript, ESLint, 786개 단위 테스트, Next.js 프로덕션 빌드 통과. ESLint에는 기존 콘텐츠 화면의 이미지 경고 1건이 남는다.
- `TEAM_V1_ENABLED=true` 로컬 브라우저에서 8개 팀 화면을 1440/390px과 다크/라이트로 확인했다. 총 32개 이미지는 `screens/`에 있다. 페이지 바깥 가로 넘침과 브라우저 오류가 없었다.
- 전체 브라우저 회귀 검사는 153건 통과·12건 조건부 건너뜀·2건 시간 초과였다. 검사 중 개발 서버 재컴파일 화면이 보였던 두 시간 초과 케이스는 코드를 고정한 뒤 단독 재실행하여 2/2 통과했다.
- 최신 팀 전용 브라우저 검사는 옛 결정 링크와 8개 화면의 두 크기·두 테마를 포함해 5/5 통과했다.
- 댓글 API는 비로그인 또는 볼 수 없는 업무에서 쓰기를 막고, 보이는 업무에만 길이 제한된 활동 이벤트를 추가하는 단위 시험을 통과했다.
- DEV Supabase의 실제 마이그레이션 버전과 로컬 SQL 파일명을 일치시켰다. 적용 전 트랜잭션 롤백 시험, 적용 후 이력·함수·실행 권한 확인을 통과했다. `anon` 실행은 거부된다.
- DEV에서 인증 구성원을 가정한 트랜잭션으로 회의 생성 → 후보 저장 → 시작 → 종료 → 검수·확정 → 결정 변경을 시험하고 롤백했다. 시험용 회의·업무·문서 행은 0건 남았다.
- 로그인된 Preview에서 회의·업무·일정·팀원 읽기 화면을 확인했다. 이 계정의 조회 범위에서는 회의·업무가 0건이고 팀원 목록은 표시된다.
- 운영 DB는 읽기 전용으로 대조했다. 기존 회의 엔진과 필수 컬럼은 있고 새 팀 함수는 없으며, 과거 마이그레이션에는 저장소와 다른 운영 이력 버전이 있어 전체 `db push` 대신 이번 추가형 SQL만 별도 검토·적용해야 한다.

## 아직 검증하지 않은 것

- 운영 DB에는 팀 마이그레이션을 적용하지 않았다. 실제 로그인 브라우저에서 저장·검수·병합을 커밋하는 흐름과 기존 회의/업무 데이터와의 대조는 아직 하지 못했다. 현재 계정 조회 범위의 회의·업무가 0건이고 지속 시험 기록을 만들지 않는 범위를 지켰다.
- 실제 마이크 권한·녹음 장치와 전사 서비스는 브라우저 모의 화면 검사에 포함되지 않았다.
- 운영 배포는 하지 않았다. 회사 문서 데이터는 읽기/쓰기 시험에 사용하지 않았다.

## 다음 단계

1. Preview와 DEV에서 확인된 범위를 사용자에게 공유한다. 실제 기기 녹음·전사 및 지속 기록을 이용한 병합 검증은 추가 범위로 남는다.
2. 운영 DB에는 이번 추가형 SQL 1건만 적용할 범위를 확정하고, PR 병합·Vercel 운영 배포·사후 확인에 대한 별도 승인을 받는다.
