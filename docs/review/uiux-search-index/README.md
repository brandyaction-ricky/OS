# OS-02 색인 현황·안전한 재시도·부분 검색

현재 활성 문서의 hash와 맞는 최신 작업을 문서당 한 번 집계합니다. 기존 큐의 전체 pending/running/failed/done 필드는 보존하고 coverage를 추가했습니다. 일반 사용자의 진행률은 문서 RLS 범위에 제한하며 문서 식별자·오류 원문을 반환하지 않습니다. 조회 제한 또는 조회 실패를 완전한 집계로 표시하지 않습니다. 작업 상태 기준으로 표시하므로 실제 청크 수나 검색 품질 검증률과는 다릅니다.

검색은 단어 검색 결과를 먼저 표시한 뒤 의미 검색으로 보강합니다. 늦게 도착한 이전 검색은 덮어쓰지 않으며, 보강이 실패해도 먼저 찾은 결과를 유지합니다. 단어 검색과 보강 조회 모두 요청자 RLS를 사용합니다. 첫 단어 결과 요청은 기존 검색 통계에 중복 적재하지 않으며 정확한 단어 모드는 기존 단일 검색 경로를 유지합니다. 작은 화면에서 검색 방식 버튼의 세로 줄바꿈도 수정했습니다.

색인 실패는 고정 사유로 분류하고 원문 대신 안전한 범주를 저장합니다. 재시도는 활성 문서의 현재 hash 최신 실패에 한정하고 실행 중 작업은 제외합니다. 기존 서비스 전용 os_finish_embedding_job 트랜잭션으로 청크 교체를 수행해 저장 실패 시 기존 자료를 유지합니다. 빈 문서도 완료 처리하며 보관 문서를 계속 대기열에서 반복하지 않습니다. 새 마이그레이션 없음.

## 검증

- verify: lint·타입·단위 461개·빌드 통과. 모바일 CSS와 검색 통계 중복 방지까지 포함한 최종 코드 기준.
- 최종 로컬 브라우저 60개 통과, DEV 실제 계정 시험 1개 생략.
- 모의 시험: 권한 범위/페이지 나누기, 현재 버전만 재시도, 중복 실행/부분 집계 거절, 오류 원문 차단, 공급자 분류/벡터 검사, 저장 실패 시 기존 청크 보존, 먼저 도착한 부분 결과 유지·역전 방지, CLI 조회 기본값·대상 확인.
- DEV 기존 완료 함수 존재 및 service_role 실행 허용·authenticated 직접 실행 불가를 읽기 전용으로 확인.
- migration 무결성 통과(active 19/archived 14), readyToApply false. 새 migration 없음.
- 다크·밝은 1440/390 화면 8개 확인. 프로필을 가린 로컬 데모이며 실제 DEV 데이터 캡처가 아닙니다.

미수행: 실제 DEV 저장/재시도 및 PostgreSQL 트랜잭션 장애 주입, 인증 Preview에서 부분 결과·색인 진행률, 운영 재처리와 운영 배포. 개발 자격 증명과 승인된 DB 쓰기 범위가 없습니다. 현재 완료 함수의 실 DB 동시 문서 수정 경쟁은 별도 DEV QA 항목입니다. 검색의 4초 DB 요청 제한 안에서도 단어 조회가 실패하면 결과를 만들지 못할 수 있습니다.

## 재처리 명령

관리자 사용자 세션 토큰은 OS_ADMIN_TOKEN 환경변수로 안전하게 주입합니다. 인자·로그·Git에 토큰을 넣지 않습니다. 관리자 API가 실제 권한을 검사합니다. 에이전트 키는 사용할 수 없습니다.

```sh
# 기본: 조회만. 승인된 환경 URL을 사용합니다.
node tools/retry-indexing.mjs --base https://APP_HOST --limit 25
# 대상과 영향 범위 승인 이후 현재 버전 실패만 대기열에 등록합니다.
node tools/retry-indexing.mjs --base https://APP_HOST --limit 25 --execute --confirm-origin https://APP_HOST
```

명령은 AI를 호출하지 않습니다. 실제 처리 실행은 관리자 화면의 별도 확인 동작입니다. 이 작업에서는 명령을 원격 쓰기 모드로 실행하지 않았습니다. 리다이렉트·원점 불일치·불완전한 집계에서는 실행하지 않습니다. 후속 승인 이후 개발 환경에서 실패 재현 → 소량 재시도 → 현재 문서 청크와 검색 확인 → 운영 적용 여부 판단 순서로 진행합니다.
