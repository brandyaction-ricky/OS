# 인사·노무 메뉴 배포 절차

이 변경은 기존 메뉴와 휴가 기록을 보존하고, 기능 플래그로 새 인사·노무 메뉴를 추가한다. 이메일 발송 연동은 범위에서 제외했다. 촉진 서면은 OS 알림 또는 종이 서면으로만 처리하며 이메일 발송으로 표시하지 않는다.

## 배포 전 확인

- PR의 최신 커밋에서 `npm run verify`, 기본 E2E, HR 활성화 E2E가 통과했는지 확인한다.
- 별도 DEV Supabase에 두 개의 HR migration (`20261008180150_hr_labor.sql`, `20261009022419_hr_single_read_policies.sql`)이 적용되어 있고 재실행 대기분이 없는지 확인한다. 기존 원격 migration 이력은 수정하지 않는다.
- HR 브랜치 Preview는 DEV 자원에만 연결하고 해당 브랜치의 `HR_WORKSPACE_ENABLED=true`로 확인한다. 관리·재무 권한과 일반 구성원 각각으로 UI→API→DB 권한, 계정 발급, 휴가 승인·취소, 파일 업로드, XLSX, 예약 작업 중복 실행을 검증한다.
- 실제 직원 정보나 운영 데이터를 테스트에 사용하지 않는다. 외부 공휴일 API 키가 없으면 자동 수집은 검증 대상에서 제외하고 수동 공휴일 기능만 확인한다.
- 보안 Advisor의 인증 사용자용 `SECURITY DEFINER` 함수는 함수별 권한 검사를 포함해 검토하고, 성능 Advisor 결과를 기록한다.

## 승인 후 운영 순서

운영 반영은 별도 승인 대상이다. 대상 운영 DB와 Vercel Production, 적용할 커밋, 영향 범위를 승인받은 뒤 진행한다.

1. 운영 DB 백업·복구 경로와 기존 migration 이력을 확인한다.
2. 검토한 추가형 HR migration 두 개를 운영 DB에 적용한다. seed 또는 reset은 실행하지 않는다.
3. 승인된 PR을 `main`에 병합해 Production 배포를 완료하고 배포 SHA를 확인한다. `main` push는 자동 Production 배포를 유발한다.
4. Production에 `HR_WORKSPACE_ENABLED=true`를 설정하고, 승인된 예약 작업 인증값을 공급한다. 외부 공휴일 키는 별도 선택 사항이다.
5. 운영에서 관리자·권한자·일반 구성원 메뉴/권한, 본인 휴가, 예약 작업, 오류 로그를 확인한다. 고객·직원 실데이터 변경을 수반하는 시나리오는 별도 통제 아래 수행한다.

문제가 생기면 먼저 Production의 `HR_WORKSPACE_ENABLED=false`로 새 메뉴와 API를 닫고 이전 배포로 되돌린다. 추가형 DB 객체는 즉시 삭제하지 않는다. 기존 휴가 기록과 HR 기록은 자동 동기화되지 않으므로 필요한 경우 검토된 수동 이관 절차를 따른다.
