# OS 이미지 광고 · 영상 제작과 같은 AI와 제작 컴퓨터 사용

## 담당자가 사용하는 순서

1. OS의 ‘콘텐츠 자동화 → 이미지 광고’에서 한 장 제작 또는 여러 안 테스트를 선택한다. 상품을 고른 뒤 광고 한 장은 소구점 하나를, A/B 프로젝트는 테스트할 소구점을 한 줄씩 작성한다.
2. 디자인 레퍼런스를 보고 고른다. 카피는 직접 작성하거나 구독 AI에서 초안을 받아 각 장의 소구점·제목·본문·CTA를 확인한 뒤 승인한다.
3. 게재 위치와 세이프 존을 포함한 시안 미리보기를 확인한다. ‘이미지를 출력할 컴퓨터’에서 공용 맥미니 또는 내 Mac을 고르고 미리보기 확인과 최종 출력을 요청한다.
4. 선택한 Mac이 요청을 받아 묶음 전체를 PNG로 출력·업로드한다. OS가 형식·규격·해시를 확인하면 실제 출력에서 만든 검수용 이미지를 연다.
5. 담당자가 모든 장을 확인하고 최종 검수를 완료하면 PNG와 묶음 ZIP을 내려받을 수 있다. A/B 테스트는 실제 집행 결과를 확인한 직원이 같은 프로젝트에서 승리 소재를 선택하고 다음 단계로 이어간다.

버튼별 동작과 재검수는 [이미지 광고 승인 순서](image-ad-approvals.md)에서 확인한다.

## 영상 기능에서 이어받는 범위

영상의 ‘내 AI’는 직원에게 연결된 구독 모델로 기획표를 만들며 모델 이름을 결과에 기록한다. 영상의 공용 제작 컴퓨터와 개인 컴퓨터는 기획표를 실제 파일로 만든다. 이미지 광고도 같은 역할을 사용한다. 모델을 특정 공급자나 모델 번호에 고정할 필요가 없다. 회사 크레딧을 쓰는 별도의 영상 GPT·음성 기능은 이미지 광고 작업에서 호출하지 않는다.

기준 사진 한 장과 카피 다섯 개가 있으면 Mac은 같은 사진으로 다섯 장을 만든다. 원본 사진 자체를 새로 만들 때는 이미지 생성 기능이 있는 직원 구독 AI가 원본을 생성해 프로젝트에 등록한다. 같은 파일을 다시 가져오기만 한 사례를 신규 이미지 생성 성공으로 기록하지 않는다.

메모·문장 포스터 등 글 중심 포맷에서도 원래 글과 배치를 유지한 채 배경 사진으로 이미지 테스트를 진행할 수 있다. 이 배경 사진을 포함한 묶음은 이미지 렌더러 2 이상인 Mac이 수령한다. 구 버전 Mac에서 대기 중이면 최신 제작 엔진을 적용한다. 기존 사진 칸을 이용하거나 배경 사진이 없는 묶음은 이전 엔진에서도 출력한다.

## 인수 조건

**새 레퍼런스**는 창고에서 광고를 고르거나 원본 파일을 올린 뒤 ‘이 레퍼런스로 제작’으로 시작한다. 해당 원본의 지문과 일치하는 교체 위치 파일이 있으면 저장한 영역과 디자인을 적용한다. 사진과 제목·버튼 위치를 인식한 광고는 원본에서 읽은 영역과 강조색에 맞춰 상품 사진과 승인 카피를 배치한다. 다른 새 광고는 원본에서 색과 구도를 읽어 상품 이미지와 문구로 새로 조판한다. 기존 광고 픽셀을 직접 다룰 때는 ‘원본의 교체 영역 편집’을 선택한다. 불러오지 못한 원본은 광고 파일을 올려 다시 선택한다.

사진·제목·본문·버튼의 위치와 크기를 원본 위에서 바꿀 수 있다. 기존 로고와 문구는 주변에서 찍은 색이나 같은 크기로 복사한 원본 무늬로 가리고, 배경 사진을 바꿀 때는 위에 남길 원본 장식과 둥근 모서리를 지정한다. ‘브랜드 칸 추가’를 누르면 상품에 등록된 브랜드명을 원본의 로고나 채널 이름 자리에 넣고 글자 크기와 색을 조절한다. 본문이 두 곳에 나뉜 원본은 ‘본문 두 칸에 나누기’를 사용한다. ‘교체 위치 저장’으로 같은 원본에서 다시 적용할 JSON을 내려받는다. 원본 파일이 달라지면 이 위치 파일을 적용할 수 없다.

창고 담당자는 미리보기와 별도로 제작용 원본이 있으면 해당 항목에 `- 제작 원본 · [원본 파일](https://…)`로 실제 이미지 주소를 넣는다. 제작 시 이 파일을 먼저 사용한다. 교체 위치 JSON은 제작할 파일에서 저장해 같은 항목의 `os-reference-master` 코드 블록에 넣는다. 다음 작업에서 파일 지문과 크기가 맞으면 교체 위치를 불러온다.

원본에서 배지·프로필·작은 삽화가 메시지를 전달하는 자리는 ‘그래픽 칸 추가’로 지정한다. 교체 사진의 특정 부분을 골라 쓰거나 상품 로고와 같은 별도 PNG를 올려 여러 칸에 사용할 수 있다. 원본 위에서 배치할 영역과 가져올 이미지의 자르기 영역을 따로 지정하고 실제 피드 크기에서 글자가 잘리는지 확인한다. 투명 영역과 둥근 모서리를 유지하며 굵기는 문구별로 지정할 수 있다. 같은 묶음의 모든 소구점이 승인한 그래픽과 자르기 위치를 공유한다.

담당자는 첫 소구점으로 배치를 보고 ‘카피 작성하기’로 진행한다. 제목·본문·공통 버튼 문구를 바꿀 때 원본 옆에 바로 반영된다. 카피 확정, 미리보기 확인, Mac 출력, 최종 검수 순서를 따른다. 기본 원본 디자인은 이미지 렌더러 6 이상, 그래픽 칸과 문구별 굵기는 7 이상에서 출력한다. 별도 위치 파일 없이 사진·제목·CTA를 재구성해 상품 이미지 전체와 제목 강조색을 적용하는 시안은 8 이상에서 출력한다.

**새 구도로 다시 배치**를 선택하면 이미지 렌더러 5의 위아래·좌우·사진 위 문구 조판을 이용한다. 이미 이 방식으로 승인한 프로젝트는 승인 당시 구도로 다시 연다.

**원본 위에서 직접 편집**은 이미지 렌더러 4부터 지원한다. 기존에 이 방식으로 승인한 작업은 저장된 좌표와 서식으로 재출력한다. 작업기는 설치된 이미지 엔진이 지원하는 작업만 수령한다.

**썸네일형 · 한 장면**에는 이미지 렌더러 3을 포함한 제작 엔진이 필요하다. 구독 도구가 글자 없는 원본을 만들고 OS는 업로드한 사진에서 피사체 위치를 측정한다. 포맷 견본, 직원 미리보기와 최종 PNG는 유튜브의 공통 썸네일 조판을 사용한다. 광고 규격에 맞춰 사진·제목·본문·버튼을 안전영역에 배치한다. 운영 적용 시 선택할 공용 맥미니와 개인 Mac의 제작 엔진을 갱신한 뒤 출력한다.

- 공용 대상으로 요청한 묶음과 개인 대상으로 요청한 묶음을 각각 지정된 종류의 기기에서만 처리한다. 개인 요청은 요청자의 기기로 한정한다.
- 선택한 기기가 작업을 받기 전에는 대기 상태다. 다운로드할 실제 결과는 해당 기기가 올린 PNG다. 카피 승인, 미리보기 확인, Mac의 파일 출력 완료, 담당자의 최종 검수 완료를 각각 표시해야 한다.
- 재시도 때 이전 원본과 편집 이력을 보존한다. 다른 작업·다른 직원의 파일을 결과로 제출할 수 없어야 한다.
- 운영 인수는 검수 계정과 연결된 두 기기를 사용한다. 같은 입력을 양쪽에서 출력하고 해당 프로젝트에서 실제 PNG를 내려받아 규격·문구·사진·세이프 존을 확인한다.
